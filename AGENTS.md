# AGENTS.md - Angels95 / AngelTech Engine

PS1-styled multiplayer game on raylib 5.5 with a custom OZONE world format and dedicated server. C++20, single `g++` link per target via plain Makefiles, no cmake. Full docs live in `Wiki/` (Engine-Overview, Building, Editor-Usage, LightningScript, World-Format-OZONE).

## Build

### Linux / macOS
```bash
make OTENGINE          # client -> Angels95
make AngelServ         # server, no raylib dep
make AngelMaster       # master server, no raylib dep
make ozpack            # asset packer
make -j$(nproc)        # all four
```
- raylib 5.5 must be installed system-wide (`/usr/local/lib/libraylib.a`), not vendored. `build.sh` installs it from source.

### Windows
- **w64devkit:** `.\build-native-win.ps1` (requires `C:\raylib\w64devkit`, GCC 15.2.0). Do NOT use WinGet GCC 16.1.0 - broken POSIX/UCRT headers.
- **MSYS2/MINGW64:** `.\build.ps1` (uses `mingw-w64-x86_64-raylib`; auto-builds raylib 5.5 to `~/raylib-5.5` if missing).
- **cmd:** `build.cmd [fast] [debug] [skipdata] [resetconfig]`.
- Both PowerShell scripts build all 5 targets and assemble `System/`. Flags: `-SkipData`, `-SkipClean`, `-Fast` (incremental; implies `-SkipClean`), `-Debug` (`MODE=debug`), `-ResetConfig`.
- **The config files in `System/` survive a rebuild.** `Angels95.ini`, `AngelEd.ini` and `OzServer.ini` are USER data (player settings, editor window layout, server auth tokens), not build output, so a template is only written when the file is missing. `build-native-win.ps1` and `build.cmd` re-assemble `System/` from scratch, so their cleanup is a *filtered* delete that skips those three names - a `Remove-Item *` / `rmdir /s` would destroy them (and `build.cmd` stages them through `%TEMP%` because it removes the directory itself). `-ResetConfig` / `build.cmd resetconfig` deletes them so the defaults come back; that is also the way to recover after a config-format change.
- `build-data.ps1` drives `OzPack.exe` to create `.oz*` packages from `GameData/` subdirectories.

### Build speed / iteration
Plain `make` is already incremental (objects in `build/`), but the scripts run `make clean` unless you skip it. For fast iteration:
```bash
make -j$(nproc) MODE=debug OTENGINE   # -O0 -g, no clean
.\build-native-win.ps1 -Fast -Debug -SkipData   # or: .\build.ps1 / build.cmd fast debug
```
- `MODE=debug` swaps `-O3` for `-O0 -g` (much faster compiles + symbols). Default is `release`.
- **ccache** is auto-detected on PATH (prefixes `g++`/`gcc`); disable with `CCACHE=` / force with `CCACHE=<path>`. Install: `pacman -S mingw-w64-x86_64-ccache`.
- **LLD** is auto-enabled as linker (`-fuse-ld=lld`) when `ld.lld`/`lld` is on PATH; override with `LDEXTRA=-fuse-ld=lld` or `LDEXTRA=` to disable. Install: `pacman -S mingw-w64-x86_64-lld`.
- `make help` prints the resolved `MODE`/`OPTFLAGS`/ccache/linker.

## Tests
```bash
make test   # builds + runs ALL suites, then FAILS if any failed (a crash counts)
```
Suites: `test_parser`, `test_context`, `test_registry`, `test_entity_manager`, `test_pawn_system`, `test_ozone_parser`, `test_join_uri`, `test_master`, `test_network`, `test_game_state`, `test_ozanim`, `test_ozls_writer`, `test_autoconvex`, `test_csg`, `test_surface`, `test_gametype`, `test_editorbus`, `test_assetscope`. `make test` also runs `worldcheck` over every shipped world and `tools/check_editor_objects.sh`.

- No test framework - standalone `tests/*.test.cpp` compiled directly. **Test executables land in repo root** (`./test_parser`, not `./tests/`).
- Most suites use `SERVER_CXX` + `-DOMEGA_TEST_ENV` (no raylib). **Exceptions:** `test_entity_manager` and `test_pawn_system` link raylib (Vector3/BoundingBox types).
- Single test targets: `make test_parser` / `make test_context` / `make test_registry` / `make test_ozone_parser` / `make test_join_uri` / `make test_master` / `make test_network` / `make test_game_state` / `make test_ozls_writer` / `make test_autoconvex` / `make test_surface` / `make test_gametype` / `make test_editorbus` etc. Note a single target **builds but does not run** — invoke `./<suite>` yourself.
- **Adding an AngelEd `.cpp` needs `AngelEd/Makefile` + `ci.yml` too, but you rarely need to.** `AngelEd/Source/` is split into `Core/`, `Subsystems/`, `Resources/` and `UI/`. `Main.cpp` and `UI/UiShell.cpp` are single unity TUs that `#include` the real files beside them, so adding a panel or a subsystem means adding a fragment and nothing else: one object, one Makefile rule, one CI line. The cost is that a fragment is not standalone (no forward declarations of its own, and the include ORDER is load-bearing), and the reverse hazard is gone: a fragment cannot drift out of sync with the build lists because it is not in them. **`Resources/` is the deliberate exception** - `AssetScope` and `PackageIO` are REAL objects (3 Makefile rules, 3 `ci.yml` entries) because they are shared by two panels yet used to be implemented inside one of them. `AssetScope.hpp` is Win32-free and raylib-free by design so `tests/AssetScope.test.cpp` can cover it headlessly; keep it that way.
- **Editor layer rule: `UI/` posts, it does not mutate.** No file under `AngelEd/Source/UI/` may call `PawnSystem::(Add|Spawn|Insert|Remove|Clear|Set)*`, `ZoneManager::Add*` or `OzoneLoader::Add*`. Check with a grep for those *mutations*, not for the word `PawnSystem` - `UI/` legitimately holds ~12 read accessors, so a bare grep is all false positives. Shared code that two panels use belongs in `Resources/`, not inside one of the panels: `BuildAssetScope`, `PackIntoPackage` and `HotLoadPackage` all did, and each was unreachable from the other panel except through the unity build.
- **`SelType::BRUSH` means a RENDERABLE index, and only that.** Two raycasts used to return that type: `RaycastTestBrushes` with a `GetCollisionVolumes()` index (the CSG **output**, merged AABBs, regenerated on every rebuild) and `RaycastTestOzPrimitives` with an `m_renderables` index. A brush's volume and its own mesh AABB occupy nearly the same space, so which index you got was decided by a sub-pixel distance difference — `AngelEd.log` shows four clicks on one spot yielding `Brush idx=102, 15, 14, 13, 11, 10, 9, 7`. Every consumer then read that as a renderable index, so Delete could remove a **different brush** than the one selected, and the gizmo reported a merged volume's extent (a 180x10x180 slab) as the brush's size. `RaycastTestBrushes` and the `FindRenderableByCollisionVol` workaround are **gone**; picking skips renderables for which `IsEditorPickableSurface()` is false, since every draw path skips them and an invisible AutoConvex box must not be selectable. That predicate is **one** definition ("no part of this brush is drawn", resolved per FACE) with three call sites — the viewport raycast, the per-face surface picker, and the WorldGraph brush list. It had **two** hand-copied versions, and they had already drifted: `RaycastTestOzPrimitives` skipped `SURF_COLLISION_PROXY|SURF_INVISIBLE` while `PickSurfaceFace` skipped nothing, so right-clicking an invisible AutoConvex box offered "Surface Properties" for geometry that could not otherwise be selected. **Do not add a fourth copy.** **Do not reintroduce an index-space guess** - if a selection index needs translating, that is a bug, not a lookup.
- **The brush obstacle query is a BOX query; the point query takes (x, z) and nothing else.** `WorldChunkManager::GetVolumesNear(worldX, worldZ, ...)` is for a POINT (the ground sample). The obstacle test called it with `(player.min.x, player.max.x)` - the player's **X max handed to the `worldZ` parameter** - so it queried the cells around `(x, x)` and walls were found only when `|x - z|` fell inside the 3x3-cell window (96 units). Ground clamp used `(x, z)` correctly, which is exactly why floors worked and walls did not: `World_endless_snow` spawns at `(0, -410)` and had **no wall collision at all**, as did Dust_Ravine `(-70, 0)` and Dessert_Dreams `(-72, 0)`. The fix is `GetVolumesNearBox(minX, minZ, maxX, maxZ, ...)`, whose signature makes the axis pairing explicit and whose behaviour is pinned by `tests/Csg.test.cpp`. It is latent on the two most-used dev maps (TestMap spawns at `(-2.0, 15.9)`, CitadelRuins near the origin, both `|x - z| < 35`), which is why it survived.
- **`DrawSurface` binds a per-face texture, and `Material`'s `maps` pointer is SHARED with the model.** `oz::surface::ResolveFaceTexture` (`SurfaceFlags.hpp`) is the one definition of the precedence (face `tex` path > face `texSlot` > brush-wide equivalents > the mesh's own); `OzoneLoader::ResolveFaceTextureHandle` turns it into a GPU handle, caching explicit paths in `m_faceTexCache` (freed in `Unload`). Because a copy of `Material` copies the **maps pointer**, writing `mat.maps[DIFFUSE].texture` reaches the model's own material - so the draw path saves and restores that one map around each `DrawMesh`. `texSlot=`, `surfTexSlot=`, `tex=` and every `face<name>_*` texture/UV kwarg were stored, exported and round-tripped for as long as they existed and **nothing ever bound them**; they only appeared to work after a save and reload.
- **`BuildFaceMeshes` gives each face its OWN texcoords array.** All six sub-meshes used to alias one array, so a per-face UV scale/offset could not exist. Each face now owns `indices` **and** `texcoords` (both `RL_MALLOC`), computed from `uvBase` with that face's resolved transform, and drops the three borrowed arrays (`vertices`/`normals`/`colors`) before storing - `UnloadMesh` frees every CPU array a Mesh points at, so a stored alias is the documented heap-corruption class. The texcoords must be allocated, **never** pointed at `uvBase.data()`. `ApplyRenderableUV` now calls `RebuildSurfaceMeshes` when `NeedsPerFaceDraw()`, or a brush-wide UV edit from the Properties panel would update the model's UVs and leave the geometry actually on screen stale.
- **A brush's authored `cz` is its TOP for `cyl` and `pyr`; `box` is centre-based.** `BuildCylinder`/`BuildPyramid` build with y in `[-h, 0]`, so `ComputeCollisionAABB` uses `[position.y - h, position.y]` and the exporter writes the position unchanged. Three things used to disagree: the mesh was base-at-zero, the collision AABB was centre-based (`+/- h/2`), and the exporter added a `+h/2` "compensation" for a re-centring the loader never did - which moved every cylinder and pyramid half a height **upward on every save/open cycle**. The level files are the authority: `EngineTest` comments a `cz=4 h=4` column as "spans z 0..4" and CitadelRuins a `cz=3.5 h=2` finial as "spans z 1.5..3.5", and `World_endless_snow`'s building (`cz=12 h=12`) is capped by a roof slab at `cz=12.2 h=0.4`, which only lines up if the building occupies `[0, 12]`. `cyl` also carries a real taper now (`cylRTop`/`cylRBot`/`cylSlices` on the renderable, because a mesh bbox only knows `max(rTop, rBot)`), and `pln` carries `planeN`/`planeDist` for the same reason; `StoreCylinderShape`/`StorePlaneOrientation` are the single writers of each.
- **Hand-built brush meshes live in `Source/World/BrushMesh.hpp`, and their TRIANGLE WINDING is covered by `tests/BrushMesh.test.cpp`.** The cylinder and pyramid are the two primitives raylib cannot generate (GenMeshCylinder is uniform, GenMeshPlane is always horizontal), so their geometry used to be assembled inline next to the `UploadMesh` call - where it needs a GL context and therefore could not be tested. The cylinder then shipped with **both caps wound inside-out** (the top cap faced down), which under backface culling is not "a dark lid" but **no lid at all**: you looked straight into the tube. The pyramid's six faces were inverted too, with hard-coded `(0, 0.5, 0)` normals, and no shipped world uses `pyr`, which is the only reason nobody reported it. The invariant the test enforces for every builder: for each triangle `cross(b-a, c-a)` must point AWAY from the solid. Two asymmetries are load-bearing and both look like tidiness bugs: a cap fan is `(centre, p1, p0)` for +Y but `(centre, p0, p1)` for -Y, and a pyramid side is `(base[i+1], base[i], apex)`. A cone also collapses one triangle per slice at the apex, so the builder skips it - a zero-area face has no normal and makes "every side triangle faces outward" false for a reason unrelated to winding.
- **Headroom: a gap the player can STAND in but not JUMP in is a trap, and `worldcheck` audits for it.** The body is `Height 2.8` anchored at the FEET and a jump rises `jumpSpeed^2 / (2*gravity)` = `81 / 36` = **2.25**, so a full jump needs **5.05** of clearance. A lower ceiling does not merely clip the jump: `OverlapsObstacle` returns true and `RestorePosition` rolls the whole move back - including the horizontal part - so the player appears to STICK to the wall they jumped beside, which reads as broken collision rather than as a low ceiling. Every EngineTest interior ceiling sat at 4.0 (a 1.0 clearance) for exactly that reason, and the fix is a storey height of **8.0**: the tallest standable prop is 2.5, and 2.5 + 5.05 = 7.55. Doorway openings must be **5.5** tall (a lintel below 5.05 jams a jump in the doorway), and a raised surface is only safe under a ceiling if `ceiling - surface >= 5.05`. `worldcheck`'s headroom pass samples the floor plane, takes the solids that actually CONTAIN each sample, sorts and merges their z-spans and inspects every free interval - that column formulation is what avoids the false positives a naive "lowest solid above this surface" test produces (the inside of a stepped pyramid is not a standing spot at all). It reports WARNINGS, not errors, because the shipped worlds carry pre-existing instances (crates/tops under a roof) and failing CI on unrelated content would block every change.
- **OzoneParser reports malformed input with a line number, and never throws.** `TryFloat`/`TryInt` exist because the parser called `std::stof`/`std::stoi` directly on kwarg VALUES (`gravity=`, `effect=`, `scale=`, `surfAlpha=`, ...) and an uncaught `std::invalid_argument` killed the process with no diagnostic - the same class as the malformed-vec3 crash, which was fixed with `ReadVec3` while the scalars were left behind. An unrecognised first token now names the line and token; a malformed value keeps the field's default and reports; unknown trailing tokens on **entity** lines report. Unknown kwargs on **brush** lines are still ignored silently by design - that is what makes the surface vocabulary extensible. `OzonePrimitive::line` carries the source line. NOTE: a crash in a suite prints no `FAIL`, so the CI grep misses it; `tests/OzoneParser.test.cpp` covers these cases and the suite must be run with its exit code checked.
- **AngelEd's working directory is fixed by `EnsureProjectRoot()`, the first statement in `main()`.** Almost every editor asset path is a relative literal (`GameData`, `System/AngelEd.ini`, `System/Data`), so a wrong cwd fails *selectively and confusingly* rather than loudly — a real session reported `GameData/Pawn/PawnDefs not found` and `Skybox: could not load 'sky_noon.dds'` with no obvious connection. The old code handled exactly one case (cwd's final component is literally `System`, which is what the run scripts use); `EnsureProjectRoot` adds cwd-already-a-root and a four-level walk up from the executable. **Do not add a path that resolves in only one layout** — the no-argument default world was `"../GameData/World.ozone"`, which exists in no layout (worlds are `GameData/Worlds/<Name>/World.ozone`) and contradicted the `System/AngelEd.ini` load eight lines below it; `FirstAvailableWorld()` is sorted and deterministic. A missing-`System/Data` early-out must **warn**, never `return` silently: that bare `return` is what made the cwd bug undiagnosable.
- **The WorldGraph Explorer list is derived state, refreshed by a dirty flag.** It was built once in `WM_CREATE` from `CreateAllEditorWindows` — which runs *before* the world loads — so it showed one `Map (level)` row until `Refresh` was pressed by hand; and each row's `selIndex` indexes the very vector it was built from, so a delete shifts every later row and the next right-click hits the wrong entity. Rule: `MarkWorldGraphDirty()` at the choke points (each event drain **gated on non-empty**, the Enter-key placement path that bypasses the bus, AutoConvex, `HistoryRestore`, world load), consumed **once per frame after the last drain**. `ShowWorldGraph(true)` refreshes unconditionally and the consume is gated on `showWorldGraph`, so a hidden panel costs nothing. **Setting a flag is not a mutation** — that is what keeps the layer rule intact, so do not "fix" staleness by calling `RefreshWorldGraph()` from a `Subsystems/` handler. Two calibrations: gating the drains on `!empty()` is load-bearing (ungated = 19 rebuilds/sec on an idle panel), and the gizmo release is gated on `g_gizmoHistPushed` (ungated, every plain *click* refreshes, since a pick is also a release).
- **Control IDs must be unique within a panel's window.** `ID_PAWN_SHOW_HIDDEN` and `ID_PAWN_TREE` were both `105`; it only worked because the treeview emits `WM_NOTIFY` and the checkbox `WM_COMMAND`, but neither could be `GetDlgItem`'d. **A control with a hard-coded rect in `WM_CREATE` is a bug the first time the window resizes** — the checkbox stayed at `y=228` while `LayoutPawnMgr` re-flowed the tree and buttons to `y = 41 + treeH`, a 9px desync. Add new controls to the panel's layout function and keep their handles.
- **AngelEd panels enumerate assets through `Resources/AssetScan`, not their own walk.** `ScanTextureBrowserFiles` carried a third copy of the GameData + package scan and re-derived the dedup policy from `!IsPathFile()`; it now calls `ScanAssets` and reads `ResourceEntry::fromPackage`, which the scanner states the way `AssetScopeItem` always did. **Thumbnails are built on first paint** (`BuildTextureThumbnail`) — they used to be built one per texture in GameData on every rescan, and a rescan runs on every window activation. Anything owning an `HBITMAP` must `DeleteObject` **before** clearing its vector; `ScanTextureBrowserFiles` leaked one bitmap per texture per rescan by clearing without freeing. Guard `substr(rfind('.'))` — `substr(npos)` throws on an extensionless package key.
- **A new source file must be added in THREE places** or CI breaks silently: the root `Makefile` (compile rule + `OBJS` + link), `AngelEd/Makefile` if the editor needs it, and `.github/workflows/ci.yml`'s **inline `g++` list** — CI builds AngelEd by hand rather than via `AngelEd/Makefile`, so the two can drift. `OBJS` is now the OTENGINE link's single source of truth; it previously had a duplicate hand-maintained list in the `OTENGINE` prerequisite line and the two drifted, breaking both CI jobs (see `fcbf049`).
- **Never trust a header edit to trigger a rebuild: the dependency lists were incomplete and silently so.** Both Makefiles now use `-MMD -MP` plus a make-level `-include $(wildcard $(BUILD_DIR)/*.d)`, so generated deps are authoritative and the hand-written header prerequisites are decorative. Before that, `build/OzOzoneLoader.o` listed `.cpp/.hpp/OzoneParser.hpp` but **not** `Source/World/SurfaceFlags.hpp`, which its own header includes — so changing a flag bit, or `kBackdropGain`, left a stale object in `build/` and the renderer disagreed with its own header with zero diagnostics. Two details are load-bearing and both fail confusingly if undone: the `.d` must be read by **make's** `-include` (gcc's `-include` tries to preprocess makefile text as C++), and **`.DEFAULT_GOAL := all` must precede it** (a `-included` `.d` file opens with a target line, so without it make adopts that file's first target as the default goal and bare `make` builds exactly one object and exits).
- **CI runs `make test`, whose EXIT CODE is authoritative.** It previously invoked each suite as `-./suite`, which told make to ignore the status, and the CI step compensated by grepping the log for `FAIL`. That pair had a hole big enough to drive the `0xC0000409` malformed-vec3 crash through it: a suite that CRASHES never reaches its summary line and prints no `FAIL`, so make succeeded and the grep found nothing. `make test` now records each failing suite by name, prints them and exits 1. The two rules that keep it honest are in the CI section below - do not undo them.
## Runtime config (verified)
- **Client:** reads/writes `System/Angels95.ini` for real (loaded via
  `LoadClientSettings()` before `InitWindow` so window size/VSync/MSAA apply at
  creation; saved on exit by a static dtor in `Main.cpp`). Settings are grouped
  by concern under `[AngelTech.Window]`, `[AngelTech.Render]`,
  `[AngelTech.Audio]`, `[AngelTech.Gameplay]`, `[AngelTech.Input]`,
  `[AngelTech.HUD]` and `[AngelTech.Debug]` (constants in
  `ClientSettings.hpp`); bindings stay in `[Keybinds]`. A legacy flat
  `[Settings]` block is still read per key and is migrated into those sections
  on the next save. The parser is `Source/IniConfig.hpp`.
  `SaveClientSettings` loads the file before writing and uses
  `IniConfig::SaveOrdered`, because the plain `Save()` walks unordered_maps
  (the file reshuffles on every exit) and writes only the keys it was given
  (which used to delete `[MasterServers]` on every quit). The build scripts'
  template ini is only a fallback. `[MasterServers]` (keys `Master`, `Master1`..)
  lists internet master URLs (http:// or https://), read by
  `Source/Server/Master/MasterList.hpp`. Default when unset:
`https://angels95.tribewarez.com/master`. TLS uses WinHTTP (Windows) / `curl`
(Linux) — see `Source/Server/Master/MasterHttp.hpp`; Windows links `-lwinhttp`.
  `IniConfig` strips a leading UTF-8 BOM. PowerShell's
  `Set-Content -Encoding UTF8` (the build scripts and CI) and Notepad both write
  one, and its bytes are not in the whitespace trim set — so before this the
  FIRST section of `System/Angels95.ini` never parsed and every key in it was
  dropped. Harmless while that section was the unused `[Video]` template block;
  a real bug once it holds settings.
- **Server:** `System/OzServer.ini` is a template written by build scripts -
  never read at runtime. Server behavior is controlled entirely by CLI flags
  (`--port`, `--http-port`, `--dir`, `--master`, `--master-http`, `--public-ip`,
  `--server-name`).
- `AngelEd` reads its INI (`g_config.Load("System/AngelEd.ini")`).
- **Player profiles:** `System/PlayerProfiles.ini`, written by
  `Source/PlayerProfile.{hpp,cpp}` (`PlayerProfileManager::Instance()`). Holds
  player slots (`displayName`, `modelPath`, `voiceSet`, `team`) edited in the
  title menu's Character pane (`Source/Menu/TitleMenu.hpp`). Loaded once in
  `AngelTechInit()` and re-saved on every mutation (no exit hook), so reopening
  the pane never discards edits. The struct is **raylib-free** so AngelEd and the
  server can read the same file; `SetPath()` redirects it for tests. One
  `[Profiles]` section with `Profile<N>_*` keys — **not** one section per profile,
  because `IniConfig` stores sections in an `unordered_map` and per-profile
  sections would come back in arbitrary order. Writing bypasses `IniConfig::Save`
  (unordered) to keep the file hand-editable; loading still uses `IniConfig`.
- **Profile over the wire (protocol v2):** the active profile is attached to
  `CLIENT_AUTH` as `net::ClientAuthPayload` (packed, with a `structSize`
  forward-compat field so optional fields can be appended without another bump).
  `PROTOCOL_VERSION` went 1->2 and is now actually sent and checked - it was a
  dead constant before, so there had been **no** version negotiation on the wire.
  A payload shorter than `kAuthSizeV2` is a v1 peer and is still accepted with
  generated defaults; an unrecognised `protocolVersion` is **rejected** rather
  than guessed at, because a misparse here assigns the wrong identity to a player.
  **Trust model - every field in that payload is client-claimed.** The server
  sanitises with `net::SanitizeDisplayName` (strips C0/DEL, keeps UTF-8),
  `net::SanitizeAssetRef` (ASCII only, **rejects `..` path segments**) and
  `net::ClampRequestedTeam` (out of range -> 0, never clamps onto a real team).
  `modelPath`/`voiceSet` are **opaque strings the server never opens or
  resolves** - if a future server-side loader ever consumes `modelPath` it must
  treat it as untrusted input. Display names are de-duplicated via
  `net::MakeUniqueName` because GameState persists save data keyed by name, so
  two players sharing one would collide. The server replies `PROFILE_STATE` so the
  client learns what was actually accepted instead of assuming its own values
  were honoured.
  **Team is NOT trusted and NOT assigned yet - the server has no team concept at
  all.** `ServerPlayer::team` (server-owned, always 0 today) is the only field
  gameplay may read; `requested_team` is the untrusted client hint, recorded for
  a future team system. Nothing may score or match on `requested_team`.
  Covered by `tests/Network.test.cpp` (profile round-trip and de-duplication run
  over a real loopback socket).

## Build identity, master listing and TDM teams

- **`Source/Version.hpp` is the ONE build identity.** `OZ_BUILD_VERSION` is
  injected by the build (`make BUILD_VERSION=b100`, CI sets it to
  `${{ github.ref_name }}`) and falls back to `"dev"`. It feeds the AngelServ
  startup log, `--version`, the heartbeat `gamever`, `/status`, LAN discovery,
  the title footer and About. The old `"build b58"` literal and the `"0.2.1"`
  heartbeat/`/status` constants were hand-edited and never changed: every build
  claimed the same version. **`gamever` is a build id; `proto` is the enforced
  wire id (`net::PROTOCOL_VERSION`).** Do not put the protocol number only in
  `gamever` — a client cannot compare a string.
- **`proto` is an optional heartbeat/JSON field** (`MasterProtocol.hpp`) and is
  in `/status` too; 0 means a legacy master that omitted it. The browser shows
  `Build:`/`Protocol:` and refuses a non-zero mismatch with the real reason
  (the server drops a mismatched `CLIENT_AUTH` and the client would only see a
  timeout).
- **The heartbeat limiter keys on the announced `ip:port`, not the source IP.**
  `HeartbeatLimiter` (`MasterProtocol.hpp`, unit-tested) also has a coarse
  per-source cap (10/s) and is pruned. The old per-source-only limit meant four
  servers on one `network_mode: host` VPS could never all be listed; the
  membership was decided by phase drift. `MasterUplink` also jitters its first
  send and its 30 s cadence, and logs a non-2xx HTTP heartbeat at **WARN**
  (`HttpRequest` returns true for a 400, so rate limiting used to log as INFO).
- **`publicip` is trusted only from a PRIVATE source** (`ResolveAnnouncedIp`).
  A public source already is the listed address; trusting its claim lets any
  host poison the list. The private case is the LAN / local reverse-proxy /
  Docker-DNAT case, where the claimed public address is the only usable one.

## Networked pickups (`PickupPawns` + `PawnSystem::ApplyPickupNetState`)
Three lists exist and confusing any two of them is what made pickups look broken:
1. the **server's** `ServerPickup` (authoritative, `GameState::m_worlds`),
2. the **client's shadow** `ClientPickup` (`OmegaClient::m_pickups`) — the client's view of the server,
3. the **drawn** `PickupNode` (`PawnSystem::m_pickups`) — what you actually see.
- **(2) drives (3), via `netId`.** `OmegaClient::set_on_pickups_changed` fires from a *copy* taken under `m_msg_mutex`; `Main.cpp` converts it and calls `PawnSystem::ApplyPickupNetState(net, world_index)`. Previously the collect flipped `active` on **(2)** only, so the mesh never vanished and every walk back re-requested an already-consumed pickup.
- **`PickupNode::netId` is the file-order index of the `pickup` line in `World.ozone`,** matching `seed_world_entities`' `nextPickupId++`. Both sides must keep enumerating the parsed primitives in file order or a collect targets the wrong physical pickup. `tests/GameState.test.cpp` pins the server side by re-reading the file independently.
- Matching is on `netId`, **not** `id` — `PickupNode::id` is a local handle from a counter shared with every other entity type.
- **`netId == -1` means "not the server's"** (e.g. a script `spawn_pickup`); `ApplyPickupNetState` leaves those alone rather than hiding a scripted pickup MP never owned. A drawn node with a `netId` but *no* server entry is left alone and **reported** — hiding on a partial snapshot is how a whole level disappears.
- **Nothing about a refused collect is silent.** `GameState::collect_pickup` returns a `PickupReject` (`UNKNOWN_PLAYER`/`WRONG_WORLD`/`UNKNOWN_WORLD`/`NOT_FOUND`/`OUT_OF_RANGE`), logged by the server, which then answers with a re-sync snapshot of the player's own world. Previously all four paths were a bare `return false` with no log and no reply, which turned the bug into a four-way guess.
- **Three ways state re-syncs:** the join snapshot, the server's 15 s per-player/own-world resync (UDP gives no delivery guarantee, so one lost `PICKUP_RESPAWN` used to strand a pickup permanently), and `PICKUP_RESYNC` (client-initiated, `PickupPawns` fires it when it has local pickups but no server state for the world).
- **`PickupRespawnData::typeName` is an OPTIONAL TRAILING FIELD.** Gate on `net::kPickupRespawnSizeBase`, never `sizeof()`. Requiring `sizeof()` made a client drop every message from a server predating the field — silently, a whole world's pickups at once. Same forward-compatible tail pattern as `ClientAuthPayload::structSize`; **no `PROTOCOL_VERSION` bump**, and `PICKUP_RESYNC = 26` is a new `MessageType` which is compatible by definition.
- **The snapshot must carry INACTIVE pickups too, and `active` is a second optional tail.** `send_pickup_snapshot` (join, re-sync answer, 15 s loop) uses `GameState::for_each_pickup`, not `for_each_active_pickup`. The client draws its own copy of every `pickup` line from `World.ozone`, so a pickup another player had already taken was absent from the snapshot, stayed **drawn forever**, and every walk-over was refused `NOT_FOUND` — the server had nothing to tell it. `PickupRespawnData::active` (gate on `kPickupRespawnSizeWithActive`; a shorter message means ACTIVE, because a legacy server only ever sent live pickups) makes the client apply `p.active = false`. Pinned by `test_pickup_snapshot_carries_inactive_state`.
- **`scan_worlds` must SORT `g_world_list`.** Plain co-op places every joiner in world 0, and the list came straight from `FindFirstFile`/`readdir`: Windows returns index order, Linux returns directory-hash order, so the same build started in a different world per host — the deployed fleet kept landing in `Dessert_Dreams` and the scene handshake then moved every joining client there. The sort makes world 0 deterministic (and keeps `current_map_name`/`/map` in agreement with the actual join world).
- **`g_network_world_index` must never be `-1`.** `-1` makes `PickupPawns`' `p.world_index != local_world` filter reject every pickup *and* the server's world check reject every collect, with nothing sent and nothing logged. A parse miss now keeps the previous value and warns.
- `OmegaClient::on_disconnected` clears `m_pickups`, `m_pending_collects` and `m_scores`; they are per-session server state.

## World routing (`REQUEST_WORLD` / `WORLD_CHANGE`)
- **`ServerPlayer::world_index` was written ONCE at creation and never updated**, so it was permanently `0`. There was no server-side world-switch mechanism at all, which made three authoritative checks compare against 0 forever: `collect_pickup`'s `WRONG_WORLD` reject, `MELEE_HIT`'s world match, and the 15 s per-player pickup resync. Any server whose active world was not index 0 rejected **every** collect and dropped **every** melee hit — silently except for one `OZ_WARN` on the melee path. `tests/GameState.test.cpp` had a `FIXME` acknowledging it.
- **`REQUEST_WORLD` (27) is client → server and the index is UNTRUSTED.** The client names a world by position in the server's own list, so the handler bounds-checks it against `GameState::world_count()` before it reaches anything that indexes `m_worlds`. A refused request **must be reported, not silent** — otherwise the client waits forever for a world it never got. It answers with the world the player is *actually* in, so the client reconciles rather than assuming it is lost. Re-requesting the current world still answers, so a client retrying after a lost datagram converges.
- **`WORLD_CHANGE` (28) is server → client and is sent on JOIN as well as on request.** The client's request is advisory; it must learn the server's decision rather than assume its own took. `accepted == 0` means refused and `world_index` is then where the player remains. It is sent **before** the pickup snapshot on join, because that snapshot is scoped to the player's world and the client derives its own index from this message.
- **Gate on `net::kWorldChangeSizeBase`, never `sizeof()`.** The spawn tail is optional for the same reason `PickupRespawnData::typeName` is: requiring the full size made a client drop every message from a server predating the field. **No `PROTOCOL_VERSION` bump** — a new `MessageType` is forward/backward compatible by definition, the same reasoning as `SCORE_STATE` and `PICKUP_RESYNC`. The constant is `offsetof(WorldChangeData, spawnX)` — it was briefly `spawnZ`, which excluded the FIRST spawn component and so accepted messages that could not carry a spawn at all; `test_world_change_without_spawn_tail` pins the exact offset.
- **A protocol with no caller is not a fix.** `request_world()` and `set_on_world_changed` shipped alongside the handler, and the two places that actually change the client's world still did not use them, so the client and server still disagreed after a portal. The client-side world changes are: the **portal** path (`Core.hpp`, `UpdateEntitiesSim`) and the scene handshake's `active_world` (`Main.cpp`). The portal path must call `NetworkRequestWorld(NetworkWorldIndexByName(target))`; the handshake path must **not**, because the server is the one telling us to switch. `NetworkWorldIndexByName` returns **-1** on a miss — never 0, which is a real world — so an offline single-player portal to an unloaded world still works.
- **The portal path needs the hook because Core.hpp cannot see `OmegaClient`.** Core.hpp is textually included before Main.cpp's statics exist, which is exactly why `NetworkSession.hpp` declares `extern` globals rather than exposing the client. `NetworkRequestWorld` / `NetworkWorldIndexByName` follow that same pattern: declared in the header, defined in `Main.cpp` next to `g_client`.
- **`set_on_world_changed` must write `g_network_world_index`, not just record a field.** The pickup filter (`ApplyPickupNetState`), the `m_pending_collects` path and `WeaponBehaviour`'s NPC-damage reports all read `g_network_world_index`, so if the callback only updates client-internal state the drawn world and the stamped index stay wrong. It also triggers `request_pickup_resync()`, because a world change means the current snapshot is for the wrong world.
- **The server's world is a THIRD index, distinct from the client's local one.** `OmegaClient::server_world_index()` is what the server last *told* us (`m_serverWorldIndex`, `-1` = not yet known); `g_network_world_index` is the client's own view of what it renders. They can disagree — a client that switches worlds locally without asking the server has collects the server will reject. `on_disconnected` resets both, because a stale `0` is indistinguishable from a real world 0.
- **`WeaponBehaviour` no longer reports NPC damage at all — the server is authoritative for both weapon kinds.** It used to run a second client-side NPC raycast and call `send_npc_damage` (`NPC_DAMAGE`) on top of the real path, so every trigger dealt damage TWICE: melee already goes through `FireSelectedWeapon` → `ResolveMeleeTarget` → `ReportMeleeHit` → `MELEE_HIT` (server re-validates world, reach cap, stamina, damage cap), and ranged already spawns a server projectile from `PLAYER_ACTION` that `tick_projectiles` damages. The duplicate `NPC_DAMAGE` leg validated only distance and rate — no world check, no damage cap. Both loops are gone; `WeaponBehaviour::FireWeapon` now only sends `send_weapon_fire` for ranged (melee sends nothing, `MELEE_HIT` already went out). `NPC_DAMAGE` remains client-reachable, so it is **hardened server-side on its own**: it now rejects `world_index != attacker->world_index` (as `MELEE_HIT` does) and clamps damage to `net::NPC_MAX_DAMAGE` with range `net::NPC_MAX_RANGE` (`Server.cpp` NPC_DAMAGE case).
- **`NPC_DAMAGE` does not validate `world_index` against the attacker** — it must, or in any non-zero world the lookup no-ops or hits a same-numbered NPC in the wrong world (all worlds are authored near the origin). The handler now does the same world check `MELEE_HIT` always had. (Historical: `WeaponBehaviour` once hardcoded `world_index = 0` here; that call is gone entirely now.)
- **The server IGNORES client-originated `NPC_STATE_UPDATE`.** It used to apply the client's values to `GameState` and re-broadcast them verbatim, with no ownership/range/world/rate check — unlike both neighbouring handlers. Any client could set `health = 0, active = false` on any `npc_index` in any world. No legitimate client sends it (the shipped client only *receives* it, and its NPCs are `networkControlled`), so the handler was attack surface with no caller; it is gone, and the now-dead `GameState::update_npc_state` with it. A legitimate client→server NPC report belongs on a NEW message type with real validation.

## Package system (OzPackage)
- Extensions + magic: `.ozpak`/OZPK (generic: models/scripts/shaders), `.oztex`/OZTX (textures), `.ozsnd`/OZSD (sounds), `.ozmux`/OZMX (music), `.ozone`/OZWN (worlds).
- Runtime: `PackageAssetLoader::Instance().Init()` scans `System/Data/*.oz*`. Read assets via `*WithFallback` wrappers (filesystem first, then packages). A `GameData/...` path resolves by exact key, then basename, then first-segment-stripped key.
- Models use temp-file cache in `System/Cache/` (raylib has no `LoadModelFromMemory`). A packaged `.gltf` also has its relative `"uri"` buffers extracted into the cache; without that raylib fails on the missing `.bin` beside the extracted text (`Predator.gltf` was the case that proved it).
- Packaging: `OzPack pack <magic|auto> <dir> <out>`; also `unpack`, `list`, `dir`. `build-data.ps1` drives it, one package per asset root, and **deletes the packages it owns first** (everything but `imported_*`) because a renamed folder otherwise leaves a stale `.oz*` that still resolves. Game-hierarchy content is **per-game**: `GameData/Game/<Game>/` packs to `System/Data/game_<Game>.ozpak` (a loose `.ozls` under `Game/` is warned about at repack time) — the old single `game.ozpak` layout is gone, so a second game beside `Angels95/` cannot shadow the first.
- Loose-only loaders need a package path or a release install silently drops content: the pawn `.cfg` defs are read from `pawns_defs.ozpak` via `PackageAssetLoader::ListAssetBasenames(".cfg")`, and the **server's** `load_server_pawn_defs` takes `<gamedata_dir>/Pawn/PawnDefs` so `--dir` is honoured.

## World format (OZONE) - sole source of truth
- The legacy WDL format and its fallback loader have been **removed**. OZONE + the LightningScript/Pawn entity system are the only world source of truth. A missing `GameData/Worlds/<Name>/World.ozone` is a hard error.
- Primitive ops: `add`/`sub`/`intersect` + primitives `box cyl sph pyr pln`. Per-brush kwargs: `flags=N`, `texScaleU/V`, `texOffsetU/V`, `texPath=`.
- **Authoring traps** (each of these silently does nothing, or silently does the wrong thing):
  - `texSlot` is BOTH a positional float (arg 8 for `box`, arg 9 for `cyl`, 7 for `pyr`) and a `key=value` kwarg, and both work. The kwarg reaches the brush's surface block, so it is editable per face and round-trips as `surfTexSlot=`; it used to be *parsed into `surface.def` and then ignored by both load paths*, which also silently forced the brush onto the per-face draw path with the auto-selected texture. Positional `texSlot` still sets the mesh material directly (the fast path). Auto-selection when neither is given: `h<1` -> tileset slot 1, else slot 2.
  - `scale=` (Mesh) and `radius=` (PathNode) are appended to the **positional** args vector, so they must come *after* all positional floats. `name=`, `tex=`, `anim=`, `speed=`, `next=`, `loop`, `gravity=`..`fly_mult=` are order-independent named kwargs.
  - `cyl` spans **z = [cz-h, cz]** — the authored `cz` is the *top*, not the centre; `pyr` follows the same rule. `box` is centre-based. `cyl` also honours a real taper (`rTop` != `rBot`, with slope-correct side normals) instead of collapsing to `max(rTop, rBot)`.
  - Unknown tokens on a brush line are ignored, but any **bare number** inside a trailing `#` comment is swallowed as an argument (and arg 8/9 is the texSlot).
  - There is **no quote parsing** in the parser. `texPath="my tex.png"` splits at the space. Only whole-token fields (`Mesh.*` path, `tex=`, `next=`, heightmap paths) tolerate quotes.
  - Every zone needs an explicit `name=`. Auto-generated names (`zone_sky_0`) are per-load counters and **collide across worlds**; `.ozls` defs live in one global last-writer-wins map. `LightningEntityRegistry::LoadWorldOverrides()` is called on every `LoadWorld()` to re-point that map at the world being played. `GAME`/`CAMPAIGN`/`SECTOR`/`MISSION`/`OBJECTIVE`/`TRIGGER`/`EVENT` defs are **global regardless of `sourcePath`** (`IsGlobalDefType` in `LightningEntityRegistry.cpp` — type-driven, not file-location-driven), so a mission def referenced from any world survives the re-point; do not re-derive globality from where a def file lives.
  - Only `playerstart` **#1** is ever used (`PawnSystem::GetFirstPlayerStart`) — it alone decides a level's first frame.
  - `light directional <x> <y> <z>`: the authored point is the light **SOURCE**, aimed at the world origin (see `OzOzoneLoader`). A large positive z = overhead sun.
  - `sub` carves **collision only**, never the render mesh. Build openings from separate pier/lintel boxes, never by subtracting from a solid.
  - **`sub`/`intersect` are modifiers, not shapes.** `CsgProcessor` (`Source/Physics/OzBsp.hpp`) subtracts from / intersects with solids that **already exist**. A world whose only brush is `sub box ...` has **zero** collision volumes while its render mesh still draws - it looks like a floor and the player falls straight through it. `GameData/Worlds/TestMap/World.ozone` shipped exactly this bug. Author floors as `add`.
  - **`portal` and `trigger` are BOXES, and a short line used to die silently.** Formats: `portal <targetWorld> minX minY minZ maxX maxY maxZ [spawnX spawnY spawnZ] [bidir]` and `trigger <def> minX minY minZ maxX maxY maxZ [once] [team=N]` (OZONE Z-up). Both consumers (`OzOzoneLoader::ParseOzoneEntity` and the server's HTTP serialiser in `ServerHttp.cpp`) gate on a full **6-number** tuple and drop anything shorter **with no log** — the line parses happily, never reaches `ZoneManager`/`TriggerSystem`, worldcheck stays silent, and the next editor save deletes it (a line that never reached a runtime container has nothing to export). 13 mission worlds shipped `portal <target> 0 0 0` exactly this way. `OzoneParser` now `OZ_WARN`s on <6 box numbers naming the line and the target; **the `trigger` warning counts bounds BEFORE appending `once`/`team`**, because those flags are pushed after the bounds, so 4 bounds + 2 flags = 6 numbers would sail through the gate as a "valid" box built from garbage. Pinned by `test_portal_short_box_is_not_padded` / `test_trigger_arity`. Two related rules: a trigger box that CONTAINS `playerstart` #1 fires its `on_enter` on the first sim step (`TriggerSystem::UpdateForPoint` treats "inside on the first sample" as an enter because `m_inside` starts empty), so a `once` volume placed on the spawn spends its single fire at load — author volumes off the spawn; and AngelEd re-emits `trigger` lines from the parsed entity set on save/History export (it has no trigger-placement UI — the lines are authored as text and must survive round-trips), while `portal` lines come from `ZoneManager`.
- Surface flags: `SURF_FAKEBACKDROP` (`1<<3`, zone backdrop) and `SURF_COLLISION_PROXY` (`1<<4`, generated AutoConvex box - collision only, **never drawn by `DrawWorldGeometry`**). Both round-trip through the ordinary `flags=` kwarg.
- Entities: `playerstart`, `pickup`, `zone` (zones are scripted by sibling `<name>.ozls` skyzone files; support per-zone physics kwargs `gravity=`, `jump=`, `terminal=`, `water_gravity=`, `water_drag=`, `swim_up=`, `ladder_speed=`, `fly_mult=` overriding `oz::physics::PhysicsInfo`), `npc`, `light` (point/spot/directional). Z-up axis.
- Export from AngelEd: `ExportToOzone()` in `AngelEd/Source/Main.cpp`. Reference: `GameData/Worlds/*/World.ozone`.
- Shared I/O helpers: `Source/PPGIO.hpp` (`LoadFile`, `WSplitValue`, `WReadValue`, `ToFloat`; save/config parsing only).
- World subdirs: `Models/`, `Music/`.

- **`PointRegion::primaryZoneId` and `primaryZoneType` must come from the SAME zone.** They were two different lookups of one concept: the type read `activeZones[0]` (priority-sorted by `GetActiveZones`) while the id read `*activeZoneIds.begin()` — the first bucket of an `unordered_set`, i.e. whichever one the integer hash landed in. With overlapping zones the two fields named **different** zones, so the player got one volume's physics while the code reasoned about another's type.
- **That bug is unreproducible by inspection, and a two-zone test CANNOT catch it.** libstdc++'s `_Hashtable` keeps ONE global forward list and prepends into it, and `Rebuild` fills the set in *reverse* priority order — so the priority winner is inserted **last**, and while every id lands in a **distinct bucket**, iteration is reverse-insertion order and `begin()` returns the winner *by construction*. The disagreement needs a **bucket collision**, i.e. two ids differing by a multiple of the 13-bucket count. That is reachable: `ClearZones()` does not reset `m_nextZoneId`, and `RemoveZone` exists for the editor's delete flow, so session ids are neither dense nor bounded. `tests/OzPawnSystem.test.cpp` pins the invariant with four overlapping zones whose ids collide mod 13 — and `test_point_region_primary_matches_type` fails on the old code. **Do not "simplify" that test back to two zones**; it would go green against the bug it was written for.
- **`OzOzoneLoader`** is a **pure data provider**: `LoadFile`/`LoadString` fill an `OzoneEntitySet` (`GetEntities()` / `GetLevelSettings()` / `GetWorldDir()`) and never mutate `PawnSystem`/`ZoneManager`. The orchestrator applies it explicitly — `Core.hpp LoadWorld()` and AngelEd's open/undo-restore paths both call
  `InjectOzoneEntities(OzoneLoader::Instance().GetEntities(), PawnSystem::Instance());`

## Audio (SoundManager)
- `Source/Audio/SoundManager.hpp/.cpp` is the **single entry point for every sound/music call**. No gameplay file should touch raylib sound handles directly.
- API: `LoadCoreSounds()` (init), `AttachReverbProcessor()` (device hookup), `ResetWorldAudio()` / `Shutdown()`, one-shots (`PlayUIClick`, `PlayChasing`, `PlayDeath`, `PlayCollision`, `PlayTextNoise`, `PlayScream`, `LoadPawnScream`, `StartWalkLoop`/`StopWalkLoop`), music (`PlayWorldMusic(assetPrefix)`, `StopWorldMusic`, `Update()`, generic `Play/Stop/UpdateStream` for caller-owned handles), zone audio (`UpdateSoundZones(region)`, `UpdateReverb(region)`), script audio (`PlayScriptSound(path)`, `PruneScriptSoundCache`).
- Per-world audio state (world music, zone ambience handle, reverb hook, script sound cache) lives in SoundManager — the `g_prevSoundZone`/`g_defaultWorldMusic`/`g_ambienceHandle`/`g_wasInReverb` globals are gone from `Core.hpp`.
- `LightningScript play_sound` routes through `SoundManager::PlayScriptSound` and is **package-aware** (`LoadSoundWithFallback`), so `.ozsnd` assets resolve.
- `GameplaySoundProfile` is consumed **only** by `SoundManager::UpdateSoundZones`; `ZONE_GAMEPLAY_SOUND` volumes are excluded from the LightningScript `on_enter`/`on_exit` zone hooks in `Main.cpp` because they are handled here instead. The profile fields `music_on_exit`, `sfx_on_combat` and `volume_mult` are editor-authored but not yet consumed.
- `DspReverb` (Schroeder reverb) stays a standalone all-static DSP; only `SoundManager` drives `SetMix`/`SetDecay`.
- **Data-driven sound stats** (`.ozls`): `PlayStatSound(path, volume, pitch)` is the ONE entry point for any stat-driven one-shot — do **not** add per-stat `Play*` methods; it shares the script-sound cache so it is package-aware and a `.wav` used by both a `play_sound` opcode and a `fire_sound` stat loads once. `StartLoopSound(key, ...)`/`StopLoopSound(key)`/`IsLoopPlaying(key)` are the **keyed** loop API; the old single `WalkingSound` handle could not express two interchangeable loops (walk/run). Loops are re-triggered from `Update()` because raylib drains a `PlaySound`'d stream, and `ResetWorldAudio()` releases them or they outlive a world load. The preloaded `GameSounds` handles stay the **fallback layer** for unauthored keys.
- Weapon keys: `fire_sound`, `swing_sound`, `hit_sound`, `reload_sound`, `equip_sound` + `_volume` (default 1.0) / `_pitch`. Player keys on `Player.ozls`: `jump_sound`, `land_sound`, `walk_sound`, `run_sound`, `hurt_sound`, `death_sound` + `_volume`. **Author them quote-free and space-free** — the stats parser stores a string verbatim, does not strip quotes, and stops at the first space, so a quoted or spaced path silently never resolves.
- **Fire/swing audio must stay behind the `result < 0` gate** in `WeaponBehaviour::FireWeapon`. `FireSelectedWeapon` returns `-1` when it refuses to shoot — on cooldown, out of stamina, or when it silently auto-reloads — so playing earlier fires a gunshot on every click of an empty magazine.
- `hit_sound` fires inside the `!blocked` melee branch only: a swing that stops at a wall takes the else-branch, which deliberately runs no `on_hit`, so it must not make a connect sound either.
- **Fallbacks are asymmetric on purpose.** `fire_sound`/`equip_sound` fall back to a global handle so an unauthored weapon still shoots; `swing_sound`/`hit_sound`/`reload_sound`/`land_sound` do **not**, because there is no honest generic clip for "a blade connected" and borrowing one makes every swing in every level identical.
- **Hurt is split from death.** Both hurt paths (network `PLAYER_HURT` in `Main.cpp`, script `damage` opcode in `Core.hpp`) route through `PlayerController::PlayHurt(fatal)`. `PLAYER_HURT` fires on *every* point of damage, so routing both to `PlayDeath()` made a firefight sound like a montage of deaths.
- `WeaponBehaviour::SelectedWeaponStat` reads `runtimeStats` **before** `def->stats.floats`, matching `FireSelectedWeapon`'s `readStat` lambda. It used to read the def only, so a script-set override was invisible to recoil/damage while the projectile path saw the overridden value.

## `.ozls` writer (Script/OzlsWriter)
- `Source/Script/OzlsWriter.{hpp,cpp}` is the write counterpart to `LightningScriptParser`. **Raylib-free** on purpose: AngelEd links it and it runs in the headless test harness.
- **Patch, do not regenerate.** `PatchOzlsStats(path, edits)` rewrites individual `key = value` lines inside the existing `stats { ... }` span. The tempting alternative (parse → mutate → re-serialise) is simpler but destroys every comment, the key order, and any key the parser only warned about — `reverb_mix`/`reverb_decay` in the shipped zone defs are exactly that. An edit from the Property Window must be a one-line diff, so `tests/OzlsWriter.test.cpp` asserts the *untouched* content byte-for-byte.
- `SerializeEntityDef` is only for a file with **no** `stats` block (a new def) and for the round-trip test. It cannot preserve comments because it never sees them. Output is sorted (from `unordered_map`) so a save does not reshuffle itself.
- Empty `StatEdit::value` means **erase**. An erase against a file with no `stats` block is rejected rather than fabricating an empty block to hold the deletion.
- The block scan must ignore a `}` that appears **after an `=`** on a line — `stats` lines are flat assignments, so that brace belongs to the value. Without the check the block ends early and an edit appends a duplicate key instead of updating in place. Braces inside quotes are also skipped.
- **Build wiring is three places:** root `Makefile` (`OBJS` + a `test_*` rule), `AngelEd/Makefile` (`CORE_OBJS` or `RESOURCES_OBJS`), and `.github/workflows/ci.yml`'s inline `g++` list - CI compiles the editor by hand rather than via the Makefile, so missing it fails the link there only. **Diff the two AngelEd lists when changing either:** they must agree apart from `OTCustom_stub.o`, which exists only because CI links a stub where the Makefile links `-l:Custom.so`.
- **FIXED — and the recorded cause was WRONG.** This entry used to read: *"Known pre-existing bug: `LightningScriptParser` segfaults on an unquoted `}` inside a stats value — it walks past the end of the content."* The crash was real; that cause was not. An unquoted `}` parses fine — the value scan stops before it and the block ends normally — and `test_parse_unquoted_brace_is_not_a_vec3` now pins that so nobody goes hunting for a brace bug that is not there. The real trigger is a **malformed vec3**: `ParseStatBlock` and the skyzone `fog_color`/`ambient_light` branch each read `(r,g,b)` by blind position (three `ReadNumber` calls, two `ReadToken`s between them, no check that anything was there), so a short or unclosed tuple ran `ReadNumber` off the end of the content and `std::stof("")` threw `std::invalid_argument` out of a parser with no handler. Measured `0xC0000409` on `k = (1,2)`, `k = (` and `k = ( )`.
- **Both copies now route through `LightningScriptParser::ReadVec3`.** There were two hand-written copies of that read and they had already drifted (one had a bounds guard, the other did not) — the same shape as the `fogFactorAt` copies. `ReadNumber` is also non-throwing now (returns 0 with a warning), because it is public on the class and a throwing number reader is a trap for every future caller.
- **The separator handling had a second bug the crash was masking.** It used `ReadToken` to skip the comma, and `ReadToken` reads until whitespace — so it only worked because every shipped vec3 has a **space** after each comma (`fog_color = (179, 179, 204)`). `(1,2)` silently lost the second component and then read on into whatever followed. `ReadVec3` consumes exactly one separator character, so both spellings work.
- **Recovery, not merely not-crashing:** a malformed vec3 costs that ONE stat plus a warning, and the rest of the block still parses. It is deliberately **not** recorded as `(0,0,0)` — a silent black colour is a plausible-looking wrong value, which is worse than a missing one.

## Script/entities: GameUI + SlotBar (HUD object bar)
- `GameData/Tex/Engine/GameUI.ozls` (`EntityType::GAMEUI`) is the **authored** source of the player's HUD object bar: one atlas `texture =` plus a `slot_rects` stat.
- `Source/Pawn/AngelPlayer/GameUi.{hpp,cpp}` = C++ bridge. Exposes the texture plus `SlotCount()`/`SlotRect(i)` and the layout stats (`hud_width_pct`, `hud_bottom_margin`, `icon_inset`, `show_slot_numbers`, `show_slot_name`). Still data-only — it never draws.

It also does click-to-select.

## Editor asset managers (Model Browser + Texture Manager)
- Both panels present assets as the **same two-root tree**, never one flat list, so it is always obvious whether an asset is an editable file or a package record:
  - `(GameData)` — loose files under `GameData/`, nested by their real folder
  - `(Packages)` — assets that only exist inside a `.oz*` package
- A **`.oz*` file is the only thing treated as a package**; anything reachable on disk is a real file even when a package holds a same-named copy. Implemented once in `BuildAssetScope()` (`Resources/AssetScope.cpp`) over `AssetScopeItem`/`AssetScopeNode` (`Resources/AssetScope.hpp`) and shared by both panels, so the two can't drift.
- Leaves carry their index into the caller's vector in the treeview `lParam`; folders carry `-1`. **Treeview selection arrives as `WM_NOTIFY`/`TVN_SELCHANGEDW`, not `WM_COMMAND`.**
- Each panel has a search box that re-filters the already-loaded in-memory entries (no filesystem hit per keystroke). While a search is active, matching folders auto-expand; empty folders are pruned.
- Texture Manager: the tree is a **scope selector** for the thumbnail grid, not a filter of it. `UpdateTextureScopeSelection()` republishes `g_textureVisible` (indices into `g_textureFiles`) from the selected subtree; empty means "all", which is the grid's original behaviour. It is split out from `FillTextureScopeTree()` on purpose — rebuilding the tree from inside its own selection notification would destroy that selection. The grid stores a *grid position*, so always map through `TexEntryAt()`.
- **Imports pack immediately** (`PackIntoPackage`/`HotLoadPackage` in `Resources/PackageIO.cpp`): model import → `System/Data/imported_models.ozpak` (OZPK), texture import → `System/Data/imported_textures.oztex` (OZTX). The package is *appended* (existing entries read back with `OzPackageReader::Read` and rewritten), then hot-loaded via `LoadPackageFile`, so entries resolve this session and land under `(Packages)`. Requires miniz, which AngelEd already links.
- Imported textures are **free-placement assets**, not tileset entries: usable via `tex=` on `Mesh.Static`/`Mesh.Skeletal` and as a model texture, but **not** as a brush `texSlot`. The import dialog says so loudly (`kTexSlotWarning`) because `texSlot` is a bare positional float indexing `<world>/oztex/tileset/` — silently getting auto-selection back is a confusing authoring bug.

## Pawn system

- Data-driven NPC defs from `GameData/Pawn/PawnDefs/*.cfg` (name, speed, aggroRange, attackRange, damage, maxHealth, sprite_path, scream_path). Fallback hardcoded defs: Walker, Skaarj, Brute, Floater.
- **FSM is `PawnState`: IDLE, PATROL, CHASE, RETURN, DEAD** (no ATTACK state - check `Source/Pawn/OzPawnSystem.hpp:25`). State transitions fire `.ozls` script actions `on_patrol`/`on_chase`/`on_return`/`on_death` — **only if a pawn-named `.ozls` def exists in the registry** (e.g. `Walker.ozls`); without one, `scriptInstanceIndex` stays -1 and hooks never fire. Projectile kills call `TransitionState(DEAD)`.
- **A pawn's `position.y` is its FEET, and the MODEL must be offset to match.** `EnsurePawnMesh` caches `auto_ground_offset = -bounds.min.y * model_scale` (the `DrawModelEx` order is scale-then-translate, so the lowest point lands on the feet). `DrawAll` adds it; `.cfg` `model_y_offset=` overrides it. Without this every GLB whose pivot is centred was drawn with its origin on the floor, i.e. hovering by half its height — the "air floating enemy" bug. `model_scale` is part of the derivation, so changing scale cannot silently re-introduce the gap.
- **Hovering is a def property, not an accident.** Floater's `.cfg` sets `hover=1` (plus `hover_amplitude`, `hover_speed`): the vertical physics block is skipped and the model bobs around its authored spawn height. `Update` advances `hoverPhase`, `DrawAll` applies the bob; `position.y` is never written by it, so collision/ground queries stay stable.
- **Static enemy GLBs can animate through `.ozanim`.** `PawnDef::anim_file` (`animfile=` in the `.cfg`, `anim_file=` also accepted) routes `EnsurePawnMesh` through `MeshCache::GetAnimated`; `DrawAll` maps the FSM state to `anim_idle/patrol/chase/return/death` and calls `AnimatedMesh::ApplyVertexPose`. This is the only animation path for the shipped unrigged Walker/Floater/Skaarj models, and the clips are now authored: `GameData/Pawn/Pawns/Anims/{Walker,Skaarj,Floater}.ozanim`, generated from the models' own geometry by `tools/gen_pawn_anims.py` (Idle/Walk/Run/Death, plus a wing-flap `Fly` for the wasp). **Re-run the generator after changing one of those models** — the clips encode vertex indices. Two things the generator had to get exactly right and both are silent when wrong: (1) raylib loads glTF meshes in **flat `nodes[]` order with their node transform chain baked in**, not in `meshes[]` order — walking `meshes[]` mis-orders the spider (`[337,1261]`, not `[1261,337]`) and the wasp (`[918,864,34,34]`) and every offset lands on the wrong vertex; (2) offsets are in the transformed space (those files use scale 100 + a -90° X rotation), because they are added to `mesh.vertices`. Verify a regenerated clip by the load log: `AnimatedMesh: ... (N clips, M vertices)` must report the same `M` raylib does.
- **A dead pawn is a CORPSE for `kPawnCorpseSeconds` (6 s), not an instant despawn.** `ApplyPawnDamage` used to set `active = false` on the same frame it fired `on_death`, and `DrawAll` skips inactive pawns — so the DEAD branch, and with it every `anim_death` a def can author, was unreachable, and no body was ever drawn. Now `state = DEAD` + `deadTimer`, `active` stays true, `DrawAll` draws it (the DEAD clip is clamped at its last frame by `SyncPawnAnim`, because `ApplyPose` wraps with `fmod` and a corpse would otherwise stand up and replay; the hover bob is also forced to 0 so a dead Floater stops floating up and down), and `Update`'s corpse branch (which runs **before** the `networkControlled` early-out, so server-owned corpses tick too) despawns it when the window closes. `IsPlayerAttacked`/`ResolveMeleeTarget`/`ApplyPawnDamage` already filter DEAD, so a corpse is never re-hit. Pinned by `test_dead_pawn_keeps_drawing_until_corpse_timer_expires`.
- **A server-owned NPC's `yaw` and `state` were on the wire and thrown away.** `NpcStateUpdateData` carries position **and** yaw **and** state; `Main.cpp`'s NPC sync copied only `position`, and because `Update()` returns early for `networkControlled` pawns the local FSM (and therefore `p.state` / `p.velocity` / `p.yaw`) never advanced. Every multiplayer NPC slid around playing the idle clip, facing its spawn yaw. The sync now casts `NpcState` straight to `PawnState` (same order: IDLE/PATROL/CHASE/RETURN/DEAD), copies `yaw` **directly** (the server stores degrees — `GameState::tick_npcs` does `atan2 * RAD2DEG` — and `Pawn::yaw` is degrees; a RAD2DEG here yaws everything 57x), and derives velocity from the snapshot delta into `Pawn::netPrevPosition`/`netHasPrev`, holding the last direction between ~10 Hz packets and zeroing it once the server reports IDLE. A server death (`active` false) starts the same corpse window locally — including the gore, which used to be the only thing in that branch.

- **Facing is smoothed and velocity-driven.** `Update` turns `Pawn::yaw` toward the movement direction at 8 rad/s (shortest angle); `DrawAll` uses it for every loaded model. Billboards (no model could be loaded) still face the camera. The old code re-derived yaw only for skeletal pawns, so static models were glued to the camera and animated ones snapped.
- **Client patrol follows `PathNode`s when the world has them.** `TickPatrol` is a member now (it reads `m_pathNodes`): it walks to the target node, advances along `next` by NAME (falling back to loop/first/next), and only uses the legacy arc when the world authored no nodes. The server already did this; the client ignored the graph entirely.
- **`PawnSystem::Spawn` resets every per-instance field it recycles.** Slots come from `m_freeIds`, so hover phase, `pathTarget`, forced clip, `scriptInstanceIndex` and the cached `mesh` must all be cleared or a respawn inherits the previous occupant's state (and its model).
- **`Despawn`/`DespawnAll` MUST ZERO the released sprite/scream handles.** `m_pawns` is a GROWING vector and `DespawnAll` walks every slot, including ones the next world does not reuse (a 14-NPC world followed by a 12-NPC one leaves two). Raylib takes `Sound`/`Texture2D` BY VALUE, so its internal reset only zeroes the copy; the slot kept the dead handle. `UnloadSound` frees the `AudioBuffer` the stale pointer names, so the next world change freed it a second time — the reported crash was the first portal after a campaign launch that had first loaded Aethelgard_Ruins (14 NPCs) and then Sektor_01 (12), i.e. the third `LoadWorld` of the process. `UnloadTexture` double-unload is mostly benign (raylib reuses GL names), which is why this only reproduced with audio live (`--shot` skips `InitAudioDevice`, so the shot harness cannot reproduce it). Pinned by `test_despawn_all_zeroes_stale_handles` (spawn 14 → DespawnAll → spawn 12 → fake stale scream on the two unreused slots → DespawnAll twice).
- **`LoadWorld` must clear `m_skyZones` too.** `ClearSkyZones()` had no in-source caller, so every transition kept the previous world's sky zones (all worlds are authored near the origin, so the old zone matched first) and leaked its sky texture. It is now in the clear block next to `ClearWindZones`.
- NPCs attack only via melee range check (+ projectiles) - no ranged NPC fire. Scream plays on IDLE→CHASE (4s per-pawn cooldown).
- Multiplayer: server-owned NPCs carry `npc_type` in `NpcStateUpdateData` and spawn with `networkControlled=true` (local FSM + contact damage skipped; server applies damage via `PLAYER_HURT`).
- Animated pawns: `.cfg` keys `mesh_type` (`static`/`skeletal`) + `anim_idle/patrol/chase/return/death` + `anim_speed`, plus `animfile=` for an external vertex-keyframe clip on a static model. A skeletal pawn uses `oz::SkeletalMesh` (GLB/GLTF/IQM only — not OBJ) and maps `PawnState` to a clip; a static pawn with `animfile=` uses `oz::AnimatedMesh`. Yaw tracks movement for any loaded model (see above); only billboards fall back to camera-facing.
- **Every `.cfg` field the client reads, the editor must read too, or the editor silently shows something else.** The editor's PawnDef loader in `AngelEd/Source/Main.cpp` used to parse only name/speed/ranges/sprite_path/scream_path, so `model_path`/`mesh_type`/`model_scale`/`anim_*` stayed empty and `EnsurePawnMesh` returned null — the editor rendered every enemy as its `sprite_path`, which for Walker/Brute/Skaarj is a 32x32 placeholder, while the game showed the real GLBs. Keep the two parsers in step (client: `Core.hpp`'s AngelTechInit block).

## EngineBillboard (sprites / authoring gizmos)
- `Source/Renderer/EngineBillboard.hpp` draws every non-model billboard: pickups, player-start/light/zone/emitter gizmos, and (in the editor) NPC sprites. If it breaks, all of them vanish at once and it reads as "enemies/pickups are not visible".
- **`MakeBillboardQuad` must use one array per vertex attribute.** It was rewritten in `cf3159c` to a hand-built XY quad but packed position+UV into ONE interleaved array and then handed that array to `mesh.vertices` as if it were positions-only, with `mesh.texcoords = v + 12`. Both reads were garbage — the four "vertices" were not the corners — so every billboard drew as a degenerate sliver. Separate `v`/`uv`/`n` arrays is the only correct form.
- **`triangleCount` is the number of TRIANGLES, not the index count.** The same commit set `mesh.triangleCount = 6` for a 2-triangle quad; `DrawMesh` draws `triangleCount * 3` indices, so it read 18 from a 6-element array.
- **raylib 6.0's `LoadModelFromMesh` does NOT upload the mesh to the GPU** (earlier raylib did). `s_BillboardModel` had `vaoId == 0` and every `DrawModelEx` of it rendered nothing. `EngineBillboard::Init()` now calls `UploadMesh(&s_BillboardModel.meshes[0], false)` explicitly. A future raylib upgrade/downgrade should re-check this — the failure is silent (the model loads, `meshCount > 0`, and just never draws).
- **A mesh's CPU arrays are freed by `UnloadMesh`, so they must be heap copies.** `MakeBillboardQuad` once pointed `mesh.vertices`/`texcoords`/`normals`/`indices` at `static float[]` storage. `EngineBillboard::Shutdown()` → `UnloadModel` → `RL_FREE` then called `free()` on non-heap pointers, and Windows reported `STATUS_HEAP_CORRUPTION` (`0xC0000374`) at the end of EVERY run - after the frame had rendered, in a free that names raylib's own `rlUnloadRenderBatch`/`UnloadMesh`, which is what makes it look like a raylib bug. `UploadMesh(&mesh, dynamic)` is a GL buffer usage hint; it does not transfer or waive ownership, whatever the second argument says. Every other hand-built mesh in the tree already allocates with `RL_MALLOC` (`OzPawnSystem`, `OzoneHeightmap`, `OzOzoneLoader`, `BrushMesh`) or drops borrowed pointers before storing (`BuildFaceMeshes`) - keep it that way.
- **`CloseWindow()` runs exactly once.** It is not idempotent-safe: a second call re-runs `rlglClose()`, whose `rlUnloadRenderBatch()` double-frees the default render batch. A `--shot` run ends both loops through a flag (the outer loop tests it) so the single call at the end of `main()` is the only one; the GPU teardown (`UnloadRenderTexture`, `EngineBillboard::Shutdown`, `SurfaceMaterial`/`Skybox`/`SkyMaterial`, `OzParticleSimulationManager::Shutdown`) therefore runs for shot runs too, while the context is still alive. Do not "unwind the loop" by closing the window early.

## Mesh / entity taxonomy
- `Source/Renderer/Mesh/` — `oz::Mesh` base, `oz::StaticMesh`, `oz::SkeletalMesh` (clips + stateless `ApplyPose`), and the internal `oz::MeshCache` (owned by `PawnSystem`; intentionally leaked so GL unloads never run after `CloseWindow`). Names are namespaced because raylib also defines `::Mesh`/`::Model`/`::Transform`.
- Model+clips are shared per asset; **per-instance playback state** (`animClip`/`animTime`) lives on the `Pawn`/`MeshObjectNode` — apply pose then draw immediately.
- **Never name raylib's bone/keyframe fields directly — the local toolchain is raylib 6.0 while CI pins 5.5** (`Mesh.boneIds`→`boneIndices`, `Model.boneCount`→`Model.skeleton.boneCount`, `ModelAnimation.frameCount`→`keyframeCount`). `OZ_MESH_BONE_INDICES`/`OZ_MODEL_BONE_COUNT` (`SkeletalMesh.hpp`) and `OZ_ANIM_KEYFRAME_COUNT` (`SkeletalMesh.cpp`) are the ONLY places allowed to name them; the `#else` branch is the 5.5 spelling CI compiles, so a version change costs one `#if`, not a tree-wide search. `oz::BoneIdsFitSkeleton(Model)` is the fit test (every vertex bone index < the loaded skeleton's bone count) used by the view-model's skeletal auto-enable; a mesh with bone indices and NO skeleton must return false.
- **`kSkeletalClipFps` is 60, because raylib resamples every glTF/GLB clip at 60 fps.** `rmodels.c` sets `keyframeCount = duration*GLTF_FRAMERATE + 1` with `GLTF_FRAMERATE` 60, so seconds→frame must use 60. Both defaults were 30, which played every shipped clip at **half speed** and made `ClipSeconds()` report twice its real duration (the view-model's reload stretch hid it there, because it re-fits the clip to `reload_time` regardless). Use `SkeletalMesh::ClipSeconds`/`ApplyPose` without an explicit fps unless you have a reason.
- **`GetSkeletal` is the raw asset; `GetSkeletalChecked` is the safe one.** A glTF that declares several skins makes raylib keep only the first, so a mesh whose vertex bone indices belong to another skin reads past `model.boneMatrices` during CPU skinning — garbage geometry or a crash, never an error. `SkeletalMesh` measures `BoneIdsFitSkeleton` once at load (`SkeletonFits()`, warned at load), and `MeshCache::GetSkeletalChecked` downgrades an unfit asset to a `StaticMesh` (bind pose). Every ordinary consumer uses it — pawns (`EnsurePawnMesh`), pickups, `Mesh.Skeletal` props, `PlayerModel`, `CharacterPreview`, the editor's mesh loader. **The view-model deliberately uses plain `GetSkeletal`**, because its `viewmodel_skeletal = 1` stat exists to force playback past the scan; changing that would silently disable the escape hatch.
- **`MeshCache` failures retry; they do not latch.** `m_cache` now holds successes only, and a miss records `m_retryAt[key] = now + 2 s` (steady_clock, not raylib's `GetTime`). Caching `nullptr` forever meant one unlucky early load — before a package hot-loaded, or before the `.ozls` defs registered — pinned that asset to "missing" for the session and made `PlayerModel`'s own retry impossible to succeed. The gate still keeps a per-frame miss from re-parsing a model every frame.
- **`ResolveClip(preferred)`, never `if (clip < 0) clip = 0`.** Clip 0 is not an idle in general: both shipped guns export `Fire` first and the mixamo player takes are numbered in authoring order, so the bare fallback played a gunshot or an arbitrary take on a loop. `SkeletalMesh::ResolveClip` / `AnimatedMesh::ResolveClip` try the authored name, then `"Idle"`, then 0. Note raylib stores clip names in a `char[32]`, so a longer glTF name arrives **truncated** (`Armature|Armature.002|mixamo.co`) — author a ≤31-char string, or a unique substring (`Armature.002`), which `FindClip`'s substring pass resolves.
- **A `SkeletalMesh::ApplyPose` mismatch logs once instead of doing nothing.** `IsModelAnimationValid` failing (a skin dropped because the glTF declared several) used to be a silent no-op: the model stood in its bind pose with nothing in the log. `m_invalidWarned` latches one warning per asset (the method is `const` because it is apply-pose-then-draw over a shared asset, so the flag is `mutable`).
- `.ozls` `EntityType` tokens: `Mesh.Static`, `Mesh.Skeletal`, `ParticleEmitter`, `WindZone`. `LightningScriptParser` has first-class body keys `mesh_type`, `anim_idle/patrol/chase/return/death`, `anim_speed` (top-level; unknown keys are silently dropped).
- OZONE entities: `Mesh.Static <path> x y z yaw [scale=] [tex=]` and `Mesh.Skeletal <path> x y z yaw [scale=] [tex=] [anim=Clip] [speed=]`. Parsed in `OzoneParser`, loaded into `PawnSystem::m_meshObjects` by `InjectOzoneEntities`, drawn by `DrawEntities`, exported by `AngelEd` `ExportToOzone`. Client-only (not networked). AngelEd also has a `GameEngine.Mesh` tree branch (places the Model Browser selection) plus `SelType::MESH` selection, properties panel (path/texture/clip/scale/pos/yaw + Reload), delete/duplicate.
- PS1 look: model textures get `TEXTURE_FILTER_POINT` in `oz::Mesh::Load`.

## Backface culling — one tracked flag (`Source/Renderer/CullState.hpp`)
- **`Source/Renderer/CullState.hpp` is the ONLY place allowed to touch culling.** `oz::SetBackfaceCulling(bool)` is the setter; `oz::ScopedCullOff` is the RAII guard. Nobody calls `rlEnable/rlDisableBackfaceCulling()` directly. Header-only + inline on purpose: a `.cpp` would mean editing the root `Makefile`, `AngelEd/Makefile` AND the inline g++ list in CI.
- **Why it exists:** three modules each toggled culling with raw rlgl calls and each remembered the result in its own private bool. `Core.hpp` turned it ON after the skybox and never turned it off; `SurfaceMaterial` tracked `m_cullOff`; AngelEd set it from inside `if (s_skyTex.id > 0)`, so a world with no skybox never set it at all and inherited the previous frame. Restores then restored the wrong thing.
- **The visible symptom was "some models are missing".** `tools/convert_fbx.ps1` bakes a Z-up -> Y-up rotation into the character/pawn/weapon GLBs, which flips triangle winding on a lot of them; drawn culled, such a model is *completely invisible*. Generated OZONE brushes keep correct winding, so they were fine — which is exactly why it read as a content bug and not a renderer bug. It silently affected the player character, the view-model, `Mesh.*` props and pickup models.
- **Rule:** imported assets opt OUT (`oz::Mesh::Draw`/`DrawSubmesh`/`DrawMatrix` each wrap in `ScopedCullOff`); generated world geometry stays culled.
- **The editor passes its intent in:** `OzoneLoader::Draw(camera, cullBackfaces = true)` APPLIES the value through the tracked setter rather than inheriting it. AngelEd passes `ViewMode != LightingMode::WIREFRAME`. It is a parameter, not an include of `LightingMode`, because `OzOzoneLoader` also builds into `worldcheck` and the headless tests.

## Player character model (`Source/Renderer/PlayerModel.*`, `GameData/Tex/Global/Models/Player.ozls`)
- One shared asset for every remote player, resolved through an **ordered fallback chain**, first that loads wins, and the winner is logged: (1) the `Player` def's `mesh`/`texture` — the authoring hook; (2) `GameData/Pawn/Player/Plague_Arcanist.glb` — the guaranteed default (rigged, embedded textures, nothing external to lose); (3) `Character_Killer_01.glb` + `.png`; (4) a primitive capsule placeholder.
- **A failed resolve must NOT latch.** `m_tried` gates only a *success*; failure backs off 2 s and retries. The old code latched on the first call regardless of outcome, so one unlucky early call (before the `.ozls` defs registered, or before a package hot-loaded) pinned the whole session to the capsule. `Invalidate()` resets it and is called from `LoadWorld()`, because `LightningEntityRegistry::LoadWorldOverrides` re-points the def map on every world load. `MeshCache` now retries a failed load after the same 2 s window, so a retry can heal a late def *and* a file/package that appeared after the first attempt.
- **Pass the real lit shader.** `DrawRemotePlayers3D(Shader)` takes `AngelTechData.Lights`. It used to pass `{0}`, and `oz::Mesh::Draw` only falls back to the model's own materials when `litShader.id == 0` — so remote players were drawn outside the game's lighting pass and read as unlit/invisible in a dim room while everything else was lit.
- **`model_height` stat** (in `kPlayerStats` for the editor panel) sets the rendered height. The character GLBs are authored in metres while `PlayerMovement::Height` is 3.0, so unscaled they draw at ~half the collision silhouette. Positive re-normalises; **negative means "authored scale, do not normalise"**.
- **`mesh_type = "skeletal"` is set now** (it was `static`, so remote players never animated). The Arcanist's 10 clips ARE named — raylib truncates them to `char name[32]`, so they arrive as `Armature|Armature.00N|mixamo.co`, not "unnamed takes". The two used are picked by measurement, not guesswork, and the rationale lives beside them in `Player.ozls`/`characters.cfg`: `.002` has the lowest joint motion (idle), `.008` the highest leg cadence (a step cycle). `PlayerModel::Skeletal()` still returns null for a character with no clips (Killer is unrigged), so `DrawInstance` just draws the static mesh.

## Lighting (LitLightning, rlights, LitFog.fs / Surface.fs)
- **There are NO shadows.** No shadow map, no depth texture, no `rlEnableShader` anywhere. `castShadow` is stored and read by nothing; `SHADOW_HI`/`SHADOW_LO`/`DIRTY_SHADOWS` have no GLSL and no CPU path and are **hidden** from the surface dialog rather than offered dead; `is_static`'s comment claims "baked into lightmap" and no lightmap exists (its only effect is to skip flicker). `Wiki/Lighting-Plan.md` Phase A is the design — one directional cascade plus analytic occlusion for point lights — and Phase B is a static bake. **Read that file before touching lighting.**
- **There is no lens flare.** `DrawLightFlares` (`Core.hpp`) is a camera-facing radial sprite at the light's own position — a bulb glow. No screen-space ghosts, no occlusion test, no view-dependent term. The editor never calls it at all, and substitutes two fixed-size wire rings, so the flare is not even authorable.
- **Three of the A.2 "known-bad" items are now FIXED** (the rest of that list at the end of `Wiki/Lighting-Plan.md` still stands): (1) the fog tint no longer costs a second 32-light loop — the in-scatter is accumulated *inside* the shading loop as `scatterAccum`, in **both** `LitFog.fs` and `Surface.fs` with identical body/constants, so a per-face brush and the wall beside it now agree; (2) `DetailTexture` is gated on `uHasDetail` (default 0, nothing uploads it), because an unbound sampler2D samples unit 0 — the diffuse — which multiplied albedo by the diffuse texture resampled at world-XZ*16 on every lit draw; (3) `if (Debug) DrawLights(); else {…}` is now additive — the whole sim/pawn/prop/particle/flare/view-model chain runs regardless, and the extra light gizmos are the only conditional part. `restore_ambient` was already fixed (`kDefaultAmbient`). Still open: `Light.Point.ozls`/`Light.Spot.ozls` are cited in code and do not exist, and `Dust_Ravine` uses `name=Light.Point` which resolves to nothing.
- **`LightNode::zoneId` is written every world load and every light apply, and read by nothing.** `AssignLightZones()` is a per-apply cost for a field with no consumer.
- **A GLSL uniform that no C++ code uploads is invisible to every constant-parity test.** See `test_light_uniform_upload_parity` above — this is the class of bug that let `period` ship as documented-but-broken.
- **`fogDensity` is an EXPONENTIAL RATE per world unit, not a multiplier on a linear ramp.** Every shipped skyzone authors 0.003..0.007, and those numbers are only coherent as a rate: the old `clamp((d-start)/(end-start),0,1) * density` produced **0.2% haze at 100 units** — fog was effectively off in all six worlds, which is why painted backdrops read as flat cardboard (nothing separated distant scenery from the wall behind it). Both live shaders now share one `fogFactorAt()` helper (and `Sky.fs` carries a third copy - see the skybox note below); `fogStart` is a hard floor and `fogEnd` is a **ceiling** on the exponential, not a multiplier (multiplying halved the haze over exactly the mid-field range that matters). **Do not let the copies of `fogFactorAt` drift** - `test_fog_curve_parity` enforces it.
- **`set_fog`/`restore_fog` must publish to `OzoneLoader::SetWorldFog`**, not just write `LitFog`'s uniforms. Measured: with `set_fog` active, `LitFog` carried density 0.0022 while `SurfaceMaterial` still carried the startup 1.0 — so every surface-flagged brush and every painted backdrop rendered with the *startup* fog while the lit geometry around it used the level's. `restore_fog` restores to the recorded `g_levelFog`, not the dead post-process `FogTint` state it used to read (which produced density 0 on one program and nothing on the other).
- **`g_levelFog` is captured PER WORLD, not once at startup.** The level's authored fog only exists in the skyzone `.ozls` and arrives as `on_enter`, so `LoadWorld` clears `g_levelFogCaptured` and the first fog application afterwards (script path or volumetric env-zone path) records itself as the restore target. It used to be captured in `AngelTechInit` from the startup literals — density **1.0**, start 10, end 100 — so every skyzone's `on_exit { restore_fog }` restored a near-solid wall of fog instead of the level's own. For the same reason the volumetric env-zone EXIT branch must restore the **LitFog `ambient` uniform** as well as `OzoneLoader::SetWorldAmbient`: it published only to the loader, so `Surface.fs` snapped back while every lit mesh kept the zone's ambient, in the same frame.
- **The light budget is 32 and it lives in THREE files that must agree**: `rlights.h`, `LitFog.fs`, `Surface.fs`. GLSL cannot `#include` the header, so **`tests/Surface.test.cpp` parses all three and fails on disagreement** — that test is the enforcement mechanism. It was 64 in C++ and 32 in both shaders, so the submission loop wrote slots the driver discards and half of the "supported" lights vanished, *which half being decided per frame by the sort*.
- **The light sort decides WHICH LIGHTS SURVIVE, so its ordering is correctness.** `LightSubmitTier()` ranks directional = 0 (global, no falloff, so distance is meaningless for it), point/spot within radius = 1, point/spot beyond radius = 2 (the shader already returns 0.0, so these are the correct ones to lose). The old comparator ranked everything by distance, and a directional light never gets a `radius` so it defaulted to 50, sorted as *culled*, and landed last. **Measured: 40 point lights plus a sun rendered byte-identically to the same level with the sun line deleted.** Tier 2 also removed the old `radius*2` slack, which spent slots on lights already invisible to every fragment.
- **`LitLightning_Update` returns the submitted count** because "is this scene lit" cannot be answered by `lights.size()`. The camera fill light was keyed off "does any LightNode have `active` set", which stays true when every one was culled or evicted — so the fill was suppressed in exactly the case it exists to prevent, leaving a near-black scene.
- **Design to 24 world lights** (32 slots minus `MAX_TRANSIENT_LIGHTS = 8`, which are submitted *first* and cannot be evicted, so a level authored to 32 loses 8 of its own the instant a weapon fires). Dust_Ravine ships 32 and is already over budget on any frame with a live transient. Frame time is NOT the constraint: 16.67 ms (vsync) at 8 and at 64 lights, at 2560x1440.
- **`LitFog.fs` and `Surface.fs` are two hand-maintained copies of the same lighting code.** Three divergences remain (Fresnel specular, negative clamp, opt-out flags); `DetailTexture` now exists only in `LitFog` **and is gated off**, and the fog in-scatter is folded into both. **Any change to the lighting model must land in both in the same commit** - otherwise a surface-flagged brush disagrees with the room it stands in, in the same frame, which is the exact failure mode of the ambient leak and the backdrop hack.
- **The skybox is ONE implementation: `oz::Skybox` (`Source/Renderer/Skybox.hpp`), shared by the client and AngelEd.** The two used to carry separate cubes that were near-identical and had drifted - face geometry duplicated verbatim, distance 700 vs a hardcoded 1000, and fog in the client only. So the editor viewport drew the sky at a different apparent size than the game and **could not show the horizon fog the player actually gets**. `Core.hpp` and `AngelEd/Source/Main.cpp` now only choose textures and publish fog; geometry, per-face rotations, distance, the draw loop and the shader binding live in `Skybox.hpp`. Header-only for the `CullState.hpp` reason. `AngelTechData::SkyboxFace` is gone; `Source/Main.cpp` calls `oz::Skybox::Instance().Shutdown()` before `CloseWindow`. `tests/Surface.test.cpp`'s `test_skybox_has_one_implementation` reads all three files and fails if a second cube reappears (verified: reintroducing `s_skyFaces` in the editor drops it to 151/152, exit 1). **Two details it exists to catch:** `oz::SkyMaterial::Instance().Init()` must be called by *both* callers with the same cwd-relative shader dir (`AngelEd/Source/Editor.hpp` resolves it via `OTEditor.Path + "Shaders/"`), and every raylib mesh type inside that file is spelled `::Mesh`/`::Model` because `oz::Mesh` shadows raylib's inside `namespace oz`.
- **The skybox IS fogged** (`Sky.vs`/`Sky.fs` + `Source/Renderer/SkyMaterial.hpp`), but **fixing it did not fix the horizon seam, and the reason is worth recording because it was diagnosed wrong twice.** The seam is between the sky and a painted `SURF_FAKEBACKDROP` brush, NOT between the sky and world geometry: the shipped backdrop rings stand ~13 degrees *above* the horizon (CitadelRuins' is 12 boxes at radius 42 with bottoms at z=20 against a camera at z=10), so they occlude the entire band horizon fog occupies. Rendering CitadelRuins with and without the sky shader changes **0.04%** of the frame; where the horizon IS visible it is large (TestMap 14.2%). Two corrections to earlier assumptions: the `UNLIT|FAKEBACKDROP` flat branch is *not* missing fog (`Surface.fs` applies fog to every surface outside `SF_NO_FOG`/`SF_ALPHABLEND`, and a 100x `fog_density` test washes the backdrop out completely), and `SURF_FAKEBACKDROP` brushes fog **correctly for their distance** - at 42 units a 0.005 density yields ~15%, which is why they read as walls. The blocker is placement and art: a backdrop only reads as distance if it is far enough away to fog, and **the rings are load-bearing collision** - in CitadelRuins they are the arena edge, and in `World_endless_snow` the ring starts at radius 556 while the outermost real geometry stops at 531, so that one is the map boundary too, NOT dead collision. Do not "clean up" either by adding `SURF_NO_BSP_CUTS`. See `Wiki/Lighting-Plan.md` A.2 item 11.
- **`Sky.fs` is a THIRD hand-maintained copy of `fogFactorAt()`**, after `LitFog.fs` and `Surface.fs`. `tests/Surface.test.cpp`'s `test_fog_curve_parity` extracts all three bodies, strips comments and whitespace, and requires them byte-identical, and additionally asserts `Sky.fs` still **declares** all five fog uniforms it reads (a missing declaration compiles fine and renders on GLSL's defaults, which is the bug `SurfaceMaterial` shipped with). **Verified to fail**: reintroducing a clamp in `Sky.fs` drops the suite to 138/139 and exits 1. Extend that test; do not work around it.
- **Backdrop look is only half a rendering problem.** The shipped backdrops tile `bb_wall_13.dds` (a stone wall) at `texScaleU=3 texScaleV=2`; no amount of fog makes a tiled wall read as distant scenery. The gain (0.55) and the fog are now correct, but the *art* has to change for these to look like backdrops.

## Combat feedback: `CombatFX` (3D) vs `CombatFeedback` (2D)
- **Two layers, two jobs.** `Source/Renderer/CombatFX.hpp` is the **world** half — muzzle flash, impact bursts, blood, surface decals, tracers, gibs, transient lights — and is already wired at every connect site: melee (`LightningEntityManager::FireSelectedWeapon`, inside the `!blocked` branch), projectile-vs-pawn (`OzPawnSystem::UpdateProjectiles`) and projectile-vs-world (`Core.hpp`). `Source/Renderer/CombatFeedback.hpp` is the **HUD** half: hit marker, damage-bearing arc, low-health edge cue. Header-only for the usual build-wiring reason (`Skybox.hpp`/`Crosshair.hpp`).
- **Hit confirm is a local-sim fact, not a server promise.** `ConfirmHit(killed)` is called where the connect is resolved. The kill tint is only set when the LOCAL simulation knows the target died (`ApplyPawnDamage` → `state == DEAD`); MP melee confirms the connect only, because the kill is the server's call and a guess would show an amber "you killed it" on a hit the server may reject.
- **A damage bearing is best-effort, and it says so.** `PlayerHurtData` carries only victim/damage/health — no attacker — so `FeedDamageDirection` (Main.cpp, called from the `set_on_player_hurt` callback) attributes the hit to the **nearest live pawn** and skips the arc entirely when none exists. A wrong direction is worse than no direction. The bearing is captured at the hit relative to camera-forward, as an angle, so it stays correct while the player turns afterwards.
- **The bearing convention is `right = cross(forward, up)` = `(-fwd.z, 0, fwd.x)`, and the first version had the sign flipped** (a hit from the right pointed left). 0 rad = ahead, positive = right; the draw maps `(sin a, -cos a)` in screen space. Pinned by `test_combat_feedback_cues` (source at +X with forward -Z must give +PI/2).
- **All geometry scales off `GetScreenHeight()`**, never off pixels, so the marker/arc/band are the same apparent size at 720p and 4K. The low-health band's alpha was tuned against a 640x360 capture — the first range was invisible at the health fractions players actually reach.
- **Motion comfort uses an existing setting:** `g_reducedMotion` (GameplayFlags.hpp) is pushed from `!HeadBob` once per frame in `Core.hpp` — `Settings.hpp`'s globals are per-TU `static` copies, so a header-only renderer must read the pushed inline flag, not `HeadBob` directly. It turns the ~1 Hz low-health pulse into a steady band; the hit marker and arc have no shake or scaling to disable.
- **Timers advance even when the HUD is suppressed** (`--shot` hides), so a later capture cannot show a stale cue; only the drawing is gated. `Reset()` runs in `ResetSessionState()` so a level change cannot carry a damage arc across sessions.
- Verification: a standalone probe (`C:\Windows\Temp\...\fb_probe.cpp`) renders the layer without a combat session (captured early/late + at 5% health), and `test_pawn_system` covers the timer decay and the bearing sign. A validated effect spec exists for the packet (0 particles, 3 draw calls, reduced-motion path declared).

## Particles (GameEngine.ParticleEmitter)
- Emitter node defs are boxed in `PawnSystem` (`m_particleEmitters`, `AddParticleEmitter`/`GetParticleEmitters`/`ClearParticleEmitters`). OZONE line: `ParticleEmitter <type> x y z [rate life speed spread sizeStart sizeEnd r g b rEnd gEnd bEnd gravity radius dirX dirY dirZ yaw] [tex=path]`.
- **`spread` is a cone HALF-ANGLE IN DEGREES, and there is exactly one definition of the cone** (`oz::particles::ConeDirection` in `OzParticleSimulationManager.hpp`, header-only so a headless test can call it). Emitters used to treat it as a raw unit-vector offset (`dir +- spread` on each axis) while `Burst()` treated its own `spread` as degrees, so the `spread 10..20` every shipped fire emitter authors sprayed isotropically instead of forming a cone. `tests/OzPawnSystem.test.cpp`'s `test_cone_direction_is_degrees` pins the bound; the editor label reads `Spread (deg)`.
- Simulation + rendering live in `Source/Particle/OzParticleSimulationManager.*` (pool of 4096, generated soft default texture, optional per-emitter `tex=`). **Isolation contract:** it is ticked once per frame in `Core.hpp` *after* the weapon/NPC/projectile sim loop and only reads emitter defs - it never calls gameplay code, so particles can't interrupt weapon mechanics or NPC ticks. Client-only/cosmetic (not networked).
- **One 4096-slot pool is shared by three sources with THREE different claims, and the share-out is correctness.** `kGameplayReserve` (512) is a hard floor for `Burst()`; `MAX_WEATHER_PARTICLES` (1200) caps weather; `kEmitterMax` is whatever remains (2384). Before the caps, `Acquire()` simply returned nullptr when the pool filled, so a saturated ambient field silently killed muzzle smoke, impact sparks, blood and gibs **for the rest of the session** - `World_endless_snow` authors `rate 60 x life 300` twice, i.e. 59,400 steady particles of demand. `Acquire(Source)` also **evicts** the oldest ambient particle (weather before an emitter) when a gameplay claim finds the pool full, so combat feedback cannot disappear. Tags and the per-source counters (`m_live`/`m_emitterLive`/`m_weather.live`) are written ONLY in `Claim()` and released ONLY in `Retire()` - they used to be maintained by hand at four call sites, which is how the gate and the weather counter could disagree.
- **`SetEnabled(false)` RETIRES the live ambient field and stops emitter spawning.** Hiding alone left a 300-second snow emitter simulating invisibly: it spent CPU and kept its pool slots, so bursts could still be starved by an effect the player had switched off. Gameplay bursts are never retired (the toggle is a master switch for the ambient layer only). `DrawInstanced` must also apply the gate - it did not, so with particles off a single textured blood/gib particle made it draw the whole hidden ambient field.
- **Never reset `ParticlesEnabled` (or any settings-owned flag) in `LoadWorld`.** It is loaded from `Angels95.ini` before the first load and is the only thing that decides whether the ambient layer draws; `Core.hpp` used to force it to `false` on every load, three lines above the comment forbidding exactly that, which made all 42 authored emitters and every `particles` field invisible until someone found the dev Settings toggle.
- **The persisted key is `particles_enabled`, and the old `particles` key is deliberately never read.** The bug above wrote `particles=False` into the INI on exit (LoadWorld forced it false, SaveClientSettings saved it), so every existing install had a poisoned value. Reading a new key makes "absent" mean "pre-fix file -> default ON" while a value saved by this build is genuinely user-controlled. Do not add a fallback to the old key; that resurrects the poison.
- **The instanced particle path is the ONLY hand-driven GL draw in the engine, and raylib 6.0 changed four things that each silently blank it.** All four were measured (`prog=15` bound, `vao=0`, black texture, off-screen):
  1. `rlDrawRenderBatch()` now ends with `glUseProgram(0)` AND `glBindVertexArray(0)` (5.5 restored them). `BeginBlendMode` and `rlDisableBackfaceCulling` flush, so the program must be enabled and the VAO bound AFTER those calls - binding either first loses it.
  2. `BeginShaderMode` only *records* the program (`rlSetShader` never calls `glUseProgram`); call `rlEnableShader(id)` explicitly.
  3. `GetCameraMatrix()` is not the matrix the batch uploads on 6.0. Use `MatrixMultiply(rlGetMatrixModelview(), rlGetMatrixProjection())` - the exact composition `rlDrawRenderBatch` uses.
  4. `rlSetUniformSampler(loc, n)` does NOT mean "sample unit n": it takes a *texture id*, maps it into the batch's slot table and writes `1 + i`. Set a sampler with `SetShaderValue(shader, loc, &unit, SHADER_UNIFORM_INT)` instead. `rlSetTexture` is also batch-only on 6.0 (it binds nothing); use `rlActiveTextureSlot(0); rlEnableTexture(id);`.
  Any new manual draw must follow the same order: flush-triggering state -> program -> uniforms -> VAO -> texture -> draw. Everything else in the engine goes through the 2D batch or `DrawMesh`, which do this correctly.

- **Alpha-blended particles draw with the depth WRITE off** (depth test stays on) in both the instanced and immediate paths. The immediate fallback iterates the pool in arbitrary order, so with writes on a nearer quad silently erased every farther one drawn earlier. `Particles.fs` multiplies the texture's RGB (it used to read only its alpha, so `tex=` art - blood/gibs - rendered as a flat tint while the `DrawBillboard` fallback multiplied RGB, i.e. the two paths disagreed).
- **Weather spawn height follows the velocity sign.** Rising types (void/psychic) must spawn at the BOTTOM of the camera box; every type used to spawn at its top, so a rising field began 20 units overhead and drifted further up, i.e. was only visible when looking at the sky.
- AngelEd: `GameEngine.ParticleEmitter` tree leaf places a default fire emitter; `SelType::PARTICLE` select/delete/duplicate + properties (type/tex/rate/life/speed/size/spread/color) + `ExportToOzone`.

## Path nodes (GameEngine.PathNode)
- OZONE line: `PathNode <name> x y z [radius=R] [next=a,b,c] [loop]`. Links are **by node name** (not index), so the graph survives editor reordering.
- Client: nodes boxed in `PawnSystem` (`m_pathNodes`, `AddPathNode`/`GetPathNodes`/`FindPathNodeByName`/`ClearPathNodes`), loaded by `InjectOzoneEntities`. Client-side nodes are for editor placement/visualization + round-trip only (the client never runs path AI).
- Server: `ServerPathNode` + `WorldState::path_nodes`, seeded in `seed_world_entities`; `GameState::tick_npcs` PATROL follows the graph (server-authoritative — NPC positions are already networked, so no protocol change). `ServerNPC::path_target` holds the current waypoint index; when a world has no path nodes it falls back to the legacy circular patrol. `RemovePathNode` also strips links referencing the removed name.
- AngelEd: `GameEngine.PathNode` tree leaf places one at the camera; `SelType::PATHNODE` select/delete/duplicate + properties (name/radius/next-list/loop); links and selected-node radius drawn as 3D overlays; `ExportToOzone`.

## Wind zones (WindZone)
- OZONE line: `WindZone minX minY minZ maxX maxY maxZ dirX dirY dirZ strength [freq]`. Client-only/cosmetic; not networked.
- `WindZoneNode` boxed in `PawnSystem` (`m_windZones`); loaded by `InjectOzoneEntities`; `PawnSystem::SampleWind(worldPos)` returns the combined wind at a point as `(dirX, dirZ, strength, frequency)`.
- Foliage opt-in: `wind=1` on a `Mesh.Static`/`Mesh.Skeletal` OZONE line sets `MeshObjectNode::windAffected`; the editor MESH properties panel exposes a `Wind Affected` checkbox.
- Rendering: `GameData/Shaders/Lights/Wind.vs` (a copy of `Lighting.vs` plus height-weighted sine sway, pairs with `LitFog.fs`) loaded into `AngelTechData.WindShader`; `oz::SetWindUniforms` uploads `windParams/windTime/windBaseY/windHeight` per draw. `PawnSystem::DrawEntities(camera, litShader, windShader)` uses the wind shader **only** for wind-affected meshes — everything else keeps `Lighting.vs` untouched. Missing `Wind.vs` falls back to `Lighting.vs` (no sway).
- AngelEd: `WindZone` tree leaf places one at the camera; `SelType::WINDZONE` select/delete/duplicate + properties (size/direction/strength/frequency); boxes + direction arrows drawn as 3D overlays; `ExportToOzone`.

## Vertex-keyframe animation (Mesh.Skeletal `animfile=`)
- Authored **vertex-keyframe/morph** animation (not bone skeletal). Text `.ozanim` format (`Source/Package/Anim/OzAnimFormat.*`, raylib-free): `ozanim 1` / `clip "Name" fps 30 loop 1` / `key <t>` / sparse `v <index> dx dy dz` offsets added to the model's base vertices. Vertex indices are GLOBAL across the model.
- Runtime: `oz::AnimatedMesh` (`Source/Renderer/Mesh/AnimatedMesh.*`) samples the clip and CPU-uploads positions via `UpdateMeshBuffer(mesh, 0, ...)` (apply-pose-then-draw; never `UploadMesh` on a loaded mesh). `oz::MeshCache::GetAnimated(mesh, tex, animFile, ...)` (cache key includes the anim file); falls back to StaticMesh.
- `MeshObjectNode` fields `animFile`, `animSpeed`, `animPaused`, `editPose` (editor-only live pose). OZONE: `Mesh.Skeletal <path> x y z yaw [scale=] [tex=] [animfile=Environment/Anims/x.ozanim] [speed=] [wind=1]`. `speed=` / `animfile=` parsed in `OzoneParser`, applied in `OzOzoneLoader`, exported in `AngelEd` `ExportToOzone`.
- Editor: toolbar **Anim** opens the Animation panel — clip list, New/Delete, FPS/loop, Play/Pause/Stop, timeline scrub; **Convert to Animated** (Mesh properties / Entity Properties) writes a default clip under `GameData/Environment/Anims/`; **Edit Verts** enables vertex picking (click / Shift-add / Sel All), keyboard deform (U/J/H/K/Y/I move, O/L rotate; Ctrl+Z/Y undo/redo, tool-scoped) and **Add Key/Del Key** capture sparse offsets. `SelType::MESH` selection highlight + selection raycast are wired.
- Packaging: `build-data.ps1` packs `GameData/Environment` → `System/Data/environment.ozpak` (`OZPK`). Playback is client-cosmetic (not networked).

## Weapons (b54+)
- Data-driven `.ozls` entities of type `weapon`: ranged (ProjectileNode; speed/spread/damage/lifetime; `magazine`/`reload_time` stats) or melee (`reach` stat, `on_swing`/`on_hit` actions).
- Key code: `Source/Script/LightningEntityManager.cpp` `FireSelectedWeapon()` (ammo/reload/cooldown dispatch); projectile sim in `Source/Pawn/OzPawnSystem.cpp` `SpawnProjectile`/`UpdateProjectiles` (client radius 1.5) and `Source/Server/GameState.cpp` `spawn_projectile`/`tick_projectiles` (server radius 2.0 - radii intentionally differ).
- Shipped weapons: `GameData/Tex/Global/Gun/{Pistol_01,Rifle_01,etheral_waver,automag,flux_carbine,selenite_blade}`. `pistol_01`/`rifle_01` are ranged; `etheral_waver` is a melee sword. Map pickups use these names (`pickup pistol_01` / `pickup rifle_01` / `pickup etheral_waver`).
- **The world pickup animates through the def, not through the view-model.** `PawnSystem::DrawEntities` asks for a `SkeletalMesh` only when `edef->meshType == "skeletal"`, so `pistol_01`/`Rifle_01` now carry `mesh_type = "skeletal"` + `anim_idle = "Idle"` and a dropped gun sways on its idle clip instead of standing in its bind pose (both GLBs are fully rigged). This is independent of `viewmodel_skeletal`, which only drives the first-person copy — and because `MeshCache` keys on `K|mesh|texture`, the pickup and the held gun can share one asset, which is safe only because every draw site applies a pose immediately before drawing it.
- **FBX art pipeline:** raylib can't load `.fbx`, so `tools/convert_fbx.ps1` runs FBX2glTF (auto-downloaded to `tools/FBX2glTF.exe`, gitignored) to make `.glb` beside each FBX. FBX2glTF writes one skin per mesh part; raylib supports one skin per model. The script therefore has two paths:
  - **Animated (DEFAULT):** if a base model has `Animations/<Name>_Fire.glb` / `_Reload.glb`, `tools/merge_glb_skins.py` collapses the duplicate skins into one (it REFUSES if the skins do not list the same joints in the same order) and `tools/merge_glb_anims.py` merges the clips plus a synthesized `Idle` from the bind pose. This is how `Pistol_01.glb` and `Rifle_01.glb` ship with `Idle`/`Fire`/`Reload` and a single skeleton (5 / 9 bones, verified with `BoneIdsFitSkeleton`).
  - **Static (everything else):** `tools/flatten_glb.py` strips skins + animations and the animation-only GLBs are deleted.
  `-NoAnimated` forces the old flatten-everything behaviour and **will strip the reload clips**; `-NoFlatten` skips the static pass for a manual experiment. Only Pistol_01/Rifle_01 have animation FBX sources; automag/flux_carbine/selenite_blade are OBJ and etheral_waver is a static GLB.
- **The lit shader now handles both skinning paths.** `Lighting.vs` (and `Wind.vs`) declare `vertexBoneIndices`/`vertexBoneWeights` + `boneMatrices[64]` and apply them only when `uSkinning == 1`. `oz::Mesh::NeedsShaderSkinning()` (overridden by `SkeletalMesh`) returns true only when the raylib build is GPU-skinning (`animVertices == nullptr`); the pinned CPU-skinning build uploads posed vertices itself, so the shader must NOT transform twice. `Mesh::BindMaterial` uploads `uSkinning` on every lit draw. This was required for the re-exported clips to be visible at all.
- **View-model reload is skinned body + rigid magazine.** The base gun's `Fire`/`Reload` clips now play through `SkeletalMesh` (auto-enabled by `BoneIdsFitSkeleton`), time-scaled so the clip ends at `reload_time` (`viewmodel_anim_fps`, default 30, is the keyframe→seconds conversion). The magazine lives in a sibling `<mesh>_AdditionalMeshes.glb` (ordered `[Separated, Full/2+Bullets, OneBullet]`), is drawn with the weapon transform, and drops/reinserts on the reload timer — the clip's `Magazine` joint has no geometry bound to it. `viewmodel_attachment`, `_mesh`, `_offset`, `_scale` override the auto-probe. Procedural dip/tilt is skipped when a clip exists (mutual exclusion).
- **Per-weapon projectiles:** weapon `stats` may set `projectile_mesh` (path to a model, e.g. `Projectiles.glb`), `projectile_submesh` (mesh index for the caliber), `projectile_scale`, `projectile_color=(r,g,b)`. `FireSelectedWeapon` stamps these onto the `ProjectileNode`; `PawnSystem::DrawProjectiles(camera, shader)` draws the submesh (`oz::Mesh::DrawSubmesh`) with a tracer. Client-side visual only.
- **First-person view-model:** `Source/Renderer/ViewModel.*` draws the selected weapon attached to the camera (client-only, in `Core.hpp DrawWorld`). Weapon `stats` keys: `viewmodel_mesh`, `viewmodel_texture`, `viewmodel_offset=(x,y,z)` (camera space, z forward), `viewmodel_rot=(x,y,z)`, `viewmodel_scale`, `recoil`, `viewmodel_skeletal` (`1` = force skeletal playback, `-1` = force static — shares the world pickup's `S|` cache entry; absent/0 = auto: skeletal only when `oz::BoneIdsFitSkeleton()` confirms every vertex bone index fits the model's one loaded skeleton, so a `boneIds`-with-no-skeleton mesh stays static). Clips `Idle`/`Fire`/`Reload` come from the merged GLB (`oz::SkeletalMesh`); one-shots return to Idle, plus a procedural recoil kick / reload dip. `play_clip` reaches the view-model too (two-leg — see the game-hierarchy section): the LEM queues a `clip` command when it matches the held weapon def and `Core.hpp` drains it to `ViewModel::PlayClip(name)`. Firing is `Pawn/AngelPlayer/WeaponBehaviour.cpp FireWeapon()` and the R key trigger the clips.
  - **A viewmodel key's fallback is the DEFAULT, never the currently-held transform.** `SetWeapon` used to read `VmStatVec3(def, "viewmodel_rot", m_rot)` (and the same for offset/scale/recoil), so a weapon that authors no rotation inherited the PREVIOUS weapon's — pick up the rifle (yaw 90, scale 1.3) then an unrotated def and it rendered sideways at the rifle's offset. The offset/rot/scale are per-weapon properties.
  - **Source orientation is the asset's, and the automag family points backward at the default yaw.** `automag_lvl1`, `automag_lvl2_alt` and `automag_heavy_rifle_lvl3` are authored with the grip/stock at **-Z** and the muzzle at **+Z**, while camera-forward is -Z; they also have their long axis along Z rather than the GLB weapons' baked Y-up layout. That is why `automag.ozls` and `flux_carbine.ozls` author `viewmodel_rot = (0, 180, 0)` explicitly. A new OBJ-based weapon needs its own rotation; do not rely on the old inheritance. `automag` also had no `icon` (blank slotbar cell) — `automag_icon.png` is generated by `tools/gen_placeholders.ps1`.
- **Weapon sounds are `.ozls` stats**, not hardcoded: `fire_sound`/`swing_sound` in `WeaponBehaviour::FireWeapon`, `hit_sound` + `reload_sound` + `equip_sound` in `LightningEntityManager` via `PlayDefStatSound`. See the SoundManager section for the full key list and the authoring traps.

## Editor state
- Win32 native panels + raylib viewport. Dynamic file scanning of `GameData/` + packages. Reads `System/AngelEd.ini`.
- Lit/Unlit/Wire toggle swaps material shaders; right-click context menu exists; collision CSG runs via `OzoneLoader::RebuildCollisionVolumes` per brush `csgOp` (render meshes are not carved). Export preserves `add`/`sub`/`intersect`. See the CSG/AutoConvex section below.
- Tool modes (Cam/Move/Scale/Rotate) are wired in placement mode; Pawn-tree Weapons branch places weapon pickups; sound preview has volume + loop.
- **The animation panel previews BOTH clip kinds, but only `.ozanim` is editable.** A `Mesh.Skeletal` node is selected as the anim target like any other mesh; the panel lists the GLB's embedded clips and Play/Pause/Stop/scrub drive the node, while New/Delete/Save/Add Key/Del Key/FPS/Loop/Edit Verts are disabled (`SetSkeletalPreviewMode`) because the clip lives inside the asset. **The previewed clip goes to `MeshObjectNode::previewClip` behind `animPreview`, never to `animClip`** — `animClip` is what `ExportToOzone` writes, so scrubbing through a GLB would otherwise silently retarget the prop that ships. `Main.cpp` clears `animPreview` when the node stops being the target, and `DrawEntities` prefers `previewClip` only while `animPreview` is set. `AnimDuration()` falls back to `SkeletalMesh::ClipSeconds` so the scrub slider maps 0..1 onto the GLB clip's real length.
- **The panel has TWO refresh paths and they are not interchangeable.** `WM_USER+50` (`PopulateAnimPanel`) is the structural refresh: rebuilds the clip list, re-selects a row and repopulates FPS/loop. `EditorPanelState::kAnimPanelTick` (`UpdateAnimReadout`) is the ~10 Hz playback tick posted from `Main.cpp`: it rewrites only the status line (clip, `t x / y s`, `frame n / m`) and the scrubber position. Using the structural path per frame drops the list selection every frame; using the tick path for a structural change leaks a stale list.
- Undo/redo: full-document History (Edit menu + Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z). Snapshots serialize the whole world via `ExportToOzone`; restore uses `OzoneLoader::LoadString(text, worldDir)` (tileset-aware) followed by `InjectOzoneEntities(OzoneLoader::Instance().GetEntities(), PawnSystem::Instance())`. Cleared on new/open. The animation tool keeps its own vertex-edit undo stack. Docs: `Wiki/Editor-Usage.md`.
- **The Entity Properties panel edits `.ozls` stats.** An `Edit stats` section is generated from a per-entity-type schema (`kWeaponStats`/`kPlayerStats`/`kPawnStats`/`kLightStats` plus the game-hierarchy `kGameStats`/`kCampaignStats`/`kSectorStats`/`kMissionStats`/`kObjectiveStats`, all in `UI/Panels/PropsPanel.cpp` — the game schemas list only keys with verified runtime consumers, so an unconsumed template key shows in the read-only dump instead) — from the SCHEMA, not the authored keys, so a weapon shows stats it has never set. Apply writes only *changed* rows via `ozls::PatchOzlsStats`; a blank unauthored row is not an erase, so Apply can never strip a def. Rows have **per-row** control IDs (`ID_PP_STAT_FIELD_0 + i`) rather than shared Preview/Browse plus a cursor hit-test, which would drift from the layout.
- **The read-only dump shows only keys the schema does NOT know about.** `FillDefBlock` filters `propDefFields` against the keys it just pushed into `propDefEditable`. Repeating schema keys in both sections doubled the panel height and pushed Apply off the bottom of the screen. Nothing is hidden: a schema key is shown, just in the editable row.
- **The Properties panel scrolls** (`PropsCaptureRows`/`PropsApplyScroll`/`PropsUpdateScroll`/`PropsFitWindow` in `UI/Panels/PropsPanel.cpp`). A weapon def is ~30 rows taller than any screen, so the window is capped to the monitor work area and each child is moved by `-scrollPos`; the texture grid scrolls by painting instead because it owns no children. `PropsUpdateScroll` MUST run *after* the resize — `nPage` comes from the client height, so choosing `WS_VSCROLL` first and resizing afterwards leaves a panel that fits before the resize, does not fit after, and has no bar to scroll with. `propsPanelPos.w` went 470 -> 540 so the scrollbar does not steal value-column width.
- `FillDefBlock()` is file scope in `UI/Panels/PropsPanel.cpp`, not a lambda in `ShowPropertiesPanel` — the Script Manager's **Properties** button needs it too, and that is the only route to a def with no world instance (`Player.ozls`). `ShowDefPropertiesFor(defName)` opens the panel on a def by name and leaves `propsTargetType = -1` so the per-instance position/rotation rows are skipped.
- A def resolved from a `.oz*` **package** has no writable source, so its stat rows render read-only with an explanation rather than accepting edits that cannot be saved.
- **Which `propsTargetType` reaches a def** (`ShowPropertiesPanel`). The enum is `SelType` in `Main.cpp`, and a **missing branch means no def section at all** — that is how `SPAWN` (7) and `LIGHT` (5) lost access to their `.ozls` stats. Current routing: `3` NPC → `defName`; `4` PICKUP → `typeName`; `6` ZONE → `zone.name`; `7` SPAWN → the fixed name `"Player"` (`playerstart` carries no name, so it is resolved by constant); `5` LIGHT → `light.name`. Everything else is instance fields only.
- **The Surface Properties controls live on tab PAGES, not on the dialog.** `SpfReadControls` must resolve them through `SpfFindControl`, which searches the three `g_spfPages`; `GetDlgItem(dialog, id)` only walks immediate children, found nothing, and made Apply re-send the values loaded when the dialog opened — i.e. every Flags/Alignment/Stats edit silently did nothing. Buttons and the tab control ARE direct children, so the layout code may still use `GetDlgItem` on the dialog.
- **The frame loop syncs the gizmo back into the live selection every frame, so a subsystem that edits an entity MUST publish the new transform to the gizmo.** `PropsApply` writes position/rotation/size directly, then calls `SnapGizmoToSelection(g_sel)`; without it the next frame restored the pre-edit values and a Pos/Rot edit looked like a no-op. The same sync is why every movable `SelType` needs a branch there: `MESH`/`PARTICLE`/`PATHNODE`/`WINDZONE`/`ZONE` were missing, so the Move tool moved the gizmo and wrote nothing. A brush/pyramid/cylinder's `r->position` is its TOP; the gizmo and Properties Pos are the mesh CENTRE, so both the apply and the sync translate by the local-centre offset (`RotatedAabbY` does the same for the pick box). For `Mesh.*`, `m->position` is the model ORIGIN, not its centre — assign the centre straight into it and the prop jumps by its own local offset.
- **`AddBrushRenderable` takes a WORLD CENTRE and a SCALE that it BAKES.** It builds at `size * scale`, stores `r->scale = 1`, and derives the renderable position from the mesh's local centre (so cyl/pyr keep their top convention). Its cylinder/sphere sizes are DIAMETERS; `BuildCylinder`/`BuildSphere` take RADII. Passing the raw `size` as the radius made a placed cylinder twice the ghost's width; the same mistake in `UpdateBrushRenderable` made any Properties Apply on a cylinder explode it. `DuplicateSelectedEntity` passes the source's unscaled bbox + scale + taper and rotates in DEGREES (the loader/Add API is degrees; `r->rotation` is radians).
- **Editor shaders are PROJECT assets, not world-local.** `OTEditor.Path` is the current WORLD directory (`SetWorldDirectory`), so `OTEditor.Path + "Shaders/"` resolved to `GameData/Worlds/<World>/Shaders/` and logged "Failed to open text file ... Sky.vs" for every world. `Editor.hpp` must use `GameData/Shaders/` (and `GameData/Shaders/Lights/`), the same path the client uses.
- **A top-level `.ozls` key the parser does not recognise is DROPPED with a warning.** `Player.ozls` had `model_height = 3.0` outside `stats { }` while `PlayerModel` reads `stats.floats["model_height"]`, so the authored height never took effect. Put runtime stats inside `stats { }`; only the parser's known body keys (`mesh`, `texture`, `mesh_type`, `anim_*`, `movement_speed`, `stats`, `actions`, `variants`, fog fields) may sit at top level.

- **Panel keyboard input is centralised in `EditorUi_HandleMessage`** (`UI/UiShell.cpp`, called from `Main.cpp`'s message pump BEFORE `TranslateMessage`/`DispatchMessage`). It owns what modeless windows do not get for free: Tab/Shift+Tab walk every visible `WS_TABSTOP` descendant (including the Surface Properties tab-PAGE children — `IsDialogMessage` does not traverse pages, which is why it is not used), Ctrl+A / Ctrl+Backspace work in `EDIT`, Enter moves to the next field, Escape leaves a field then closes the panel. `CreateButton`/`CreateListBox` set `WS_TABSTOP`; a control added without it is skipped by the ring. `EditorUi_ViewportHasFocus()` gates every viewport shortcut in `Main.cpp`, so typing in a panel can never switch modes, delete the selection or toggle the heightmap.
- **The World Hierarchy is a grouped TreeView** (`WorldGraphPanel.cpp`), not the old flat ListView: groups are `Map / Brushes / Models / Meshes / NPCs / Pickups / Lights / Zones / Portals / Player Starts / Emitters / Particles / Path Nodes / Wind Zones`, built from the same live containers the viewport draws. It includes placed `Mesh.*` props, particle emitters, path nodes and wind zones, which the flat list silently omitted. Sound/music emitters are listed as `(info)` because they have no `SelType` — labelled rather than a dead selectable row. It has a filter box, **Reveal** (viewport selection → tree row; does NOT steal focus, or F3 would stop working) and **Frame Selection** (tree → camera, via the `g_editorPanels.focusSelection` one-shot). Group expansion and selection survive a rebuild; row indices are revalidated against the live container before acting.
- **Panel geometry persists** in `System/AngelEd.ini [Layout]` (saved from `DestroyAllEditorWindows`, loaded before `CreateWindowEx` so a panel never flashes at its default rect, clamped to the work area). `View → Reset Panel Layout` restores the captured defaults and maximizes the main window. The fixed-control panels (Sound/Script/Pickup/Node/Heightmap/Anim/LevelList/World Graph) now reflow on `WM_SIZE` and refuse to shrink below their content (`EnforceMinTrackSize`; the ones with real reflow handle `WM_SIZE` themselves). `View → Maximize Window` is the windowed-full-size mode.
- **The viewport draws directly to the window.** A 320×200 `Target` render texture was created and stretched over the viewport in `Main.cpp` while nothing ever rendered into it; it survived because an uninitialised texture usually has alpha 0, making the editor's output driver-dependent. `Target`, the orphan `EndTextureMode()` and that `DrawTexturePro` are gone.
- **Menu accelerators are real.** The menu advertised bare `N/O/S/P/Q` for years with no handler; they are now `Ctrl+N/O/S/P/Q` and implemented in the frame loop. The toolbar **Play** button and `File → Play Test` share `PlayTestCurrentWorld()`, so the toolbar can no longer launch a missing executable without the check the menu had.
- **Editor shortcuts are one table** (`AngelEd/Source/EditorKeys.hpp`, `[Keys]` in `System/AngelEd.ini`, edited from **Help → Keyboard Shortcuts**). Modifiers are fixed per action (Save is always Ctrl+S), capture uses `GetAsyncKeyState` because a focused Win32 panel is invisible to raylib's `IsKeyPressed`, and the menu hints are generated from the same table. Camera/numpad keys and Escape stay fixed. Conflicts swap so no action is left unbound.
- **Unsaved-document tracking:** `g_documentDirty` (inline in `Core/EditorState.hpp`, because `Subsystems/History.cpp` is a real TU) is set by `HistoryPush()` and cleared by Save/Load. The title bar shows `*`, and New/Open/`WM_CLOSE` prompt through `ConfirmDiscardDocument()` (Save / Discard / Cancel). `WM_CLOSE` is intercepted in the raylib window subclass, so cancelling leaves GLFW's close flag untouched.

## CSG + AutoConvex collision
- **The collision world is AABB-only.** `CsgProcessor` (`Source/Physics/OzBsp.hpp`) consumes nothing else, which is why a placed `Mesh.*` prop has no collision and a concave brush over-blocks. `RebuildCollisionVolumes` turns a renderable's mesh AABB into a `CsgBrush`, rotated Y-aware via `RotatedAabbY` (conservative: contains the rotated shape, never under-covers).
- `Source/Physics/AutoConvex.{hpp,cpp}` is the raylib-free voxeliser: world-space float vertex soup → AABB → grid → keep cells a triangle passes through → `ConvexBox` list. Covered by `tests/AutoConvex.test.cpp` (`make test_autoconvex`).
  - **SAT with all 12 axes** (3 box faces + 9 `cross(triEdge, boxAxis)`). Do *not* "optimise" this to Akenine-Möller's 3+3 form: that variant depends on a vertex reordering into the positive octant and is easy to get subtly wrong in a way that silently rejects *everything*.
  - **`vertFloatCount` counts FLOATS, not vertices.** An earlier `vertexCount` that was really a float count made both the bounds loop and the triangle loop index 3x past the end of the buffer, reading uninitialised memory — it showed up as proxies *inside* solid geometry and as counts that changed between runs. The parameter is named for its unit on purpose.
  - Voxelising a **surface** yields a closed shell, not a filled volume (the 2x2x2 box at 0.5 cells gives 56 cells, not 64). That is correct for collision.
  - A **zero-thickness** axis gets exactly one cell *centred* on the geometry. `floor`/`ceil` of an equal min and max is zero cells, which silently returned nothing and left planes/card meshes/flat brushes with no collision.
  - `maxBoxes` **aborts the whole build** rather than truncating. A partial hull is the exact failure the feature exists to prevent.
- **`MAX_SPLITS` is a per-BRUSH carve budget, not a cap on the world.** It was compared against the TOTAL solid count (`size() + 6 > MAX_SPLITS`, 64), so any world holding ~58 solids silently stopped carving: every later `sub`/`intersect` returned with its solids untouched, and the author saw a doorway that rendered and did not open. It is now measured against the growth caused by the brush being applied (`Apply` tracks `brushStart = Count()`), the default is 4096, and `Push` is deliberately uncapped - an `add` contributes exactly one volume, so capping it would silently drop authored geometry rather than bound pathological growth. Each abandonment logs the brush's bounds and how many overlapping solids were left **uncut**, and `CsgProcessor::overflow_count()` is surfaced as an `OZ_WARN` from `RebuildCollisionVolumes` **and** as `OzoneLoader::LastCsgOverflowCount()`, which the editor checks on world open so a pre-existing broken level is loud immediately rather than only on the next brush commit. `tests/Csg.test.cpp` pins it: 500 `add`s then a `sub` still carves (6 assertions failed on the old code).
- **Brush collision uses a conservative ROTATED AABB.** `RotatedAabbY` (`OzBsp.hpp`, raylib-free, unit-tested) transforms the eight corners of the mesh box and takes min/max, mirroring the composition `RenderableModelMatrix` applies at draw time (`Scale * RotateY * Translate`). It is the tightest axis-aligned box that CONTAINS the rotated shape: it over-covers corners but never under-covers, so a long beam rotated 90 degrees still blocks along its whole length. Before this, collision used the UNROTATED box while the renderer rotated, so a rotated brush's ends stuck out of their own collision. The zero-thickness inflation now applies to **every** axis, not just Y, because an oriented `pln` can be a vertical sheet.
- **Brush rotation was also missing from the fast draw path.** `DrawRenderable` called `DrawModel(model, position, scale, WHITE)`, which has no rotation term, so a rotated brush with no surface decoration rendered axis-aligned while the editor picked and drew its faces rotated. It is now `DrawModelEx` (the same matrix the surface path builds). Latent for shipped content only because every rotated shipped brush carries `texPath=`, which forces the per-face path.
- **`ApplyRenderableTexture` must write `surface.def.texPath` and re-derive.** It set `r->texPath` (a derived MIRROR) and left the owner empty, so the next `DeriveLegacyRenderable` - which runs on any surface edit - overwrote the mirror back to "" and the next export lost `texPath=`. Same rule as every other writer of `surface.def`.
- **`OzoneLoader::AppendAutoConvexCollision` reports the real failure and counts its appends.** `AutoConvex_Build` takes an optional `AutoConvexFail*` (`BAD_INPUT` / `DEGENERATE_GRID` / `GRID_TOO_BIG` / `OVER_BUDGET`), and the editor names the cause instead of blaming the box budget for all four (with an `AutoConvex_CountCells` pre-flight on the budget case so the author knows what it would cost). The per-box `AddBrushRenderable` return was discarded, which contradicted the "never a partial hull" contract; failures are now counted and reported, because a rejected append leaves a hole the player falls through.
- **`RebuildCollisionVolumes` Phase 2b copies brush textures by INDEX into `m_collisionVolumes`, and that is only valid when the two lists correspond one-to-one.** CSG does not preserve index order — `Subtract` replaces one solid with up to 6, `Intersect`/`MergePass` `RemoveAt` (swap-with-last) — so output index *k* bears no relation to input index *k*. The code bounded the write with `rCount < size`, which prevents an out-of-bounds write but not a **mis-mapped** one, and the comment claimed a "counts match" check that did not exist. It now checks the count and skips the copy (with a log) when they differ. Count equality is a heuristic, not a proof — CSG can split one solid and drop another and land back on the input count — but it is exact for `add`-only worlds and fails to the safe side.
- `OzoneLoader::AppendAutoConvexCollision(verts, vertFloatCount, cellSize, maxBoxes)` appends each box via `AddBrushRenderable(..., CsgOp::SOLID, SURF_COLLISION_PROXY)` then calls `RebuildCollisionVolumes()`. `AddBrushRenderable` gained an optional trailing `surfaceFlags = 0`, and can return `-1` (unknown primitive type, or a null `mdl.meshes`) — **the AutoConvex loop discards that return**, so a failed append leaves a hole in an otherwise complete hull with no log.
- **Visibility:** `DrawWorldGeometry` skips `SURF_COLLISION_PROXY` unconditionally. `Draw` (the editor's all-renderables path) skips it unless `OzoneLoader::SetDrawCollisionProxies(true)`, which the stats sidebar's **View → Collision** button drives. The dead `CollisionToggle` global in `Editor.hpp` was removed in favour of `EditorPanelState::showCollisionBounds` — two flags for one toggle is how they drift.
- AngelEd entry point: `AppendAutoConvexForSelection()` in `Main.cpp`, from the right-click menu (`IDM_APPEND_AUTOCONVEX`, gated to `SelType::MESH`/`BRUSH`). Cell size is `max(0.25, extent/16)`; budget `kAutoConvexMaxBoxes = 2048`. Skeletal meshes voxelise in their **bind pose** (poses are uploaded per frame at draw time, so no posed geometry exists to sample).
- **Both brush-commit paths go through `CommitBrushRenderable()`** (Enter-key ghost and the sidebar op buttons). It snapshots the collision-volume count, rebuilds, and if a `SUB`/`DE_RESC`/`INTERSECT` op produced no new volume it logs loudly, raises a `MessageBoxA`, and sets `EditorPanelState::collisionOpWarning` (the sidebar counter then reads `Collision: N vols << NO SOLID` and the wireframes turn red). No behaviour change — a lone `sub` is *not* auto-promoted to `SOLID`.

## Light `.ozls` defs
- `EntityType::LIGHT` (`: light`) is a **defaults layer**, resolved by the light's existing `name=` kwarg — the same lookup a zone's `name=` uses for its skyzone def, so no new OZONE kwarg and no format change. Reference def: `GameData/Pawn/Lights/Light.ozls`.
- `ApplyLightDefDefaults(node, prim)` in `OzOzoneLoader.cpp` runs in the `ENTITY_LIGHT` branch of `ParseOzoneEntity` after the positional/kwarg decode.
- **A value the light line authored always wins.** Only `effect`/`flare`/`corona` (and only when `prim.light* < 0`, i.e. the line omitted the kwarg) plus `period`, `cast_shadow`, `is_static`, `inner_cone`, `outer_cone` take effect.
- **`intensity` / `radius` / `color` / `position` / `target` are deliberately line-owned** and are not in `kLightStats`. They are positional on every light line, so a def able to override them would silently retune every already-saved level the next time the def was touched — the exact hazard the light positional/kwarg split was added to avoid.
- `inner_cone`/`outer_cone` are **cosines**, matching `LightNode` (not degrees).
- Clamp `effect` into `[NONE, LAMP]` rather than casting the float straight to the enum — a def is data, and a bad value in it must not reach memory as bits.
- `ApplyLightDefDefaultsToNode(node)` is the **code-built** entry point (the editor's `GameEngine.Light` placement). The OZONE path uses the file-static version, which needs the primitive to know which optional fields the line authored; a node built in code authored none, so every def-owned field applies. Editing `Light.Spot.ozls` must change both newly placed and loaded lights.

## Sky portals (SURF_PORTAL)
- **`SURF_PORTAL` is the sky portal**: a face carrying it shows the world's sky view instead of its texture. It is the one flag that moved OUT of the "planned" group - the dialog row is now a live `Sky Portal` checkbox (`Portal (planned)` is gone; `Mirror` is the only planned row left).
- **No stencil, no recursion, no second world render.** `oz::SkyPortal` (`Source/Renderer/SkyPortal.hpp`) renders the sky cube into a half-res `RenderTexture2D` from the **sky zone anchor** (`SkyZoneNode::position`) using the main camera's rotation/FOV. `OzoneLoader::DrawSkyPortals` then draws each portal face *where it is*, sampling that texture by **screen position** (`gl_FragCoord.xy / uViewport`). The face is its own mask and the depth test against world geometry gives occlusion for free - that is what makes the effect cheap enough to ship. Screen-space (not projective/parallax) sampling is deliberate: a sky is at infinity, so clouds must not swim when the player strafes. That is also how a UE1/2 SkyZoneInfo behaves (huge sky box, camera at the zone anchor).
- **Ordering is load-bearing in two places.** (1) The view must be rendered BEFORE `BeginTextureMode(Target)`: raylib cannot nest render textures (`EndTextureMode` rebinds the default framebuffer, not the previous one). (2) Portal faces are drawn AFTER `DrawWorldGeometry` and BEFORE `DrawGlowGeometry` - an opaque hole must be occluded by nearer geometry, and an additive glow halo must not leak through it. Each portal face is drawn in **exactly one pass**: `FaceBelongsToPass` excludes it from `Full`, `GlowingOnly` and `BackdropOnly`, and `SurfacePass::SkyPortalOnly` selects it.
- **`uViewport` is the bound FRAMEBUFFER size, not the window.** The client renders 3D into `Target`, which can be resolution-scaled, so `GetScreenWidth()` would mis-map every sample; `Core.hpp` passes `Target.texture.width/height`, the editor passes the window size. `SkyPortal` recreates its render texture when that size changes (no resize hooks needed).
- **`SURF_FAKEBACKDROP` is untouched.** The 89 painted backdrops and their collision rings keep working exactly as before; a portal is a NEW, per-face, opt-in meaning. A portal face is visual only - it still collides unless the brush also carries `SURF_NO_BSP_CUTS`, which gives both authoring modes (window vs hole) without a new concept.
- **Gated on `OzoneLoader::HasSkyPortalFaces()` and on a sky texture existing**, so worlds without a portal pay nothing and a world with no sky never renders an empty view. The view is decoded from `GameData/Shaders/SkyPortal.{vs,fs}`; a load failure logs once and the faces are skipped (they are already excluded from the world pass, so the geometry behind shows through rather than a black hole).
- Both callers wire it: `Core.hpp DrawWorld` (client) and `AngelEd/Source/Main.cpp` (editor). `SkyPortal::Shutdown()` runs with the other GPU teardown in `Source/Main.cpp` **and** the editor, before `CloseWindow()`.
- **Authoring check:** right-click a face -> Surface Properties -> Flags -> `Sky Portal`. For a see-through opening, also tick `No BSP Cuts`. `tests/Surface.test.cpp` asserts the flag is live, the panel row is enabled, and `SkyPortalOnly`/`DrawSkyPortals` still exist, so the register cannot regress.

## Post-processing (HDR -> bloom -> grade)
- `Source/Renderer/PostFX.hpp` (header-only) owns the chain: an **RGBA16F scene target**, a half-res bright pass, two separable Gaussian blur passes, a display-space grade, and an additive bloom composite. `PostFX::CreateTarget/DestroyTarget` replace `LoadRenderTexture/UnloadRenderTexture` for `Target`; `PostFX::Resolve` returns the graded LDR texture.
- **The scene target is built by hand because `LoadRenderTexture` is always RGBA8.** `rlLoadTexture(..., RL_PIXELFORMAT_UNCOMPRESSED_R16G16B16A16, 1)` + `rlLoadTextureDepth(..., true)` + `rlFramebufferAttach`; if `rlFramebufferComplete` fails it falls back to RGBA8 and the grade still works (bloom just has no headroom).
- **Every pass is a normal raylib 2D draw** (`BeginShaderMode` + `DrawTexturePro`). This is deliberate: the 2D batch binds the program, VAO, sampler and MVP correctly, so the chain never touches the raylib-6 manual-draw traps documented in the Particles section.
- **The composite uses ONE sampler per pass.** Grade and bloom-add are two separate draws (the bloom is additive) rather than one shader with two samplers, because a second sampler means binding a texture unit by hand - the exact class of bug that kept particles invisible.
- **Resolve writes to an LDR `RenderTexture2D`, not the screen**, so the existing Pixel/Jitter post shaders still draw a display-ready texture and the pause menu's frozen frame still has something correct to show. If `Resolve` returns `{0}` (shader load failure) both call sites fall back to `Target.texture`, so a missing shader cannot black out the game.
- Grade parameters live in `oz::PostGrade` (exposure 1.0, contrast 1.06, saturation 1.10, vignette 0.22, bloom threshold 0.78 / strength 0.85). **Exposure, bloom strength and vignette are player settings** (`Settings.hpp` -> `PostExposure`/`PostBloom`/`PostVignette`/`PostFXEnabled`, persisted in `[AngelTech.Render]` as `post_exposure`/`post_bloom`/`post_vignette`/`post_fx`) and are pushed into `PostFX::Grade()` every frame in `Main.cpp`. They are edited in BOTH the dev Settings panel and the title menu's Video tab, which write the same globals. Contrast/saturation/threshold remain code-side.
- **Anything that recreates `Target` must use `PostFX::CreateTarget`, never `LoadRenderTexture`.** The dev panel's "Set Resolution" button did exactly that and silently downgraded the scene to RGBA8 (losing bloom headroom until restart). Window resize, resolution-scale change and that button all go through `DestroyTarget`/`CreateTarget`.
- The world shaders gamma-correct themselves, so the grade works in display space; the float target exists for bloom headroom and a future tonemap, **not** because the scene is linear HDR yet.
- `PostFX::Shutdown()` and `DestroyTarget(Target)` run in `Source/Main.cpp` before `CloseWindow()`; the bloom targets are recreated lazily by `EnsureSize` when `Target` is recreated on a resize / resolution-scale change.
- **The backdrop rings are now SURF_PORTAL content**: CitadelRuins (12 panels), Dust_Ravine (16), World_endless_snow (16), Dessert_Dreams (16), AlShaddai_Metropolis (8), Aethelgard_Ruins (10) and EngineTest (10). They keep their collision and their `texPath`, so reverting one to a painted wall is a one-flag change (`32768` -> `8`). Sektor_02's scattered `flags=8` brushes are a skyline, not a ring, and were left alone. A ground-standing ring covers mostly below-horizon angles, so it samples the sky's horizon/fog band rather than cloud texture - that is the faithful portal result.

## Material graph (baked, `.ozmat`)

- **Authoring is a graph; the runtime is textures.** `Source/Material/OzMaterial.{hpp,cpp}` (raylib-free) parses and evaluates a small DAG into four output **gates**: `diffuse`, `alpha`, `normal`, `emissive`. Node vocabulary is deliberately tiny — `texture`, `constant`, `multiply`, `normal` (height→tangent normal) — because the editor **bakes** the graph to PNGs and the game only samples them. Adding nodes means adding a shader feature; keeping the set small is what makes a deterministic bake possible.
- **File format** `GameData/Materials/<Name>.ozmat` (text, quoted paths so spaces survive): `ozmat 1`, `material "Name"`, `node <id> <type> ...`, `output <gate> <node>[.r|.g|.b|.a|.l]`, `bake <w> <h>`, and the bake metadata `hash <fnv1a>` / `baked <albedo> <normal> <emissive>`. `output <gate> -` means the gate is deliberately unset. Unknown references, duplicate ids and **cycles are parse errors** — a cycle would otherwise recurse until the evaluator gave up.
- **The hash covers the GRAPH ONLY** (nodes + outputs + bake size), never the bake metadata, or every bake would immediately mark itself stale. `MaterialRegistry` warns once when `bakeHash != Hash(graph)`.
- **Bake is editor-only**: `AngelEd/Source/Resources/MaterialBake.cpp` decodes via `LoadImageWithFallback`, evaluates, writes `albedo.png` (RGBA; alpha gate multiplied into A), `normal.png`, `emissive.png` beside the `.ozmat`, then rewrites the file with the paths + hash. `Tools → Bake All Materials` runs every loose `.ozmat`; packaged materials are read-only. The bake output is `GameData/`-rooted so the runtime resolves it in a checkout and inside `materials.ozpak`.
- **Runtime binding**: `Source/Material/MaterialRegistry.{hpp,cpp}` loads loose `.ozmat` first, then packaged copies (basename fallback), and owns the baked `Texture2D`s (unloaded in `Shutdown`, which both clients call before `CloseWindow`). OZONE `Mesh.Static`/`Mesh.Skeletal` accept `material=<Name>`; `PawnSystem::DrawEntities` sets `oz::MeshMaterial` on the cached mesh for the draw and clears it afterwards (a shared `Mesh` must not keep a bake). `Mesh::ApplyMaterialMaps` swaps the slot's diffuse for the baked one and restores the original when no material is bound — this is why `m_baseDiffuse` exists.
- **Normal mapping is derivative-TBN.** raylib's glTF loader gives the engine no tangent attribute, so `LitFog.fs` and `Surface.fs` each build a TBN from `dFdx/dFdy` of `fragWorldPos` and the UV. Both declare the same four uniforms (`uHasNormalMap`, `uNormalStrength`, `uHasEmissive`, `uEmissiveScale`) plus the two samplers. `oz::Mesh::BindMaterial` uploads them on **every** lit draw, including `uHasNormalMap=0` for a material-less mesh, because a GLSL uniform otherwise retains the previous draw's binding.
- **Two shaders, one model.** Any material-lighting change must land in **both** `LitFog.fs` and `Surface.fs`; the parity suite (`tests/Surface.test.cpp`) already enforces the constants, and `test_light_uniform_upload_parity` covers the `Light` struct. The emissive gate is added BEFORE the gamma step so it is a light contribution, not an overlay.
- **Brush faces use the same materials.** `oz::surface::SurfaceProps::material` (string) is authored as brush-wide `surfMaterial=<Name>` (alias `material=`) or per-face `face<name>_material=`; the Surface Properties dialog's Alignment tab has a **Material (optional)** field. `SurfaceProps::IsNonDefault()` includes it, so a material-only brush takes the per-face path. `DrawSurface` resolves it through `MaterialRegistry`, overrides the diffuse map with the baked albedo, and calls `SurfaceMaterial::SetMaterialMaps` (normal/emissive + strength/scale) before `ApplyUniforms`, which uploads the four uniforms on **every** face (zeros included) so a material cannot leak to the next face. The parser tests (`tests/OzoneParser.test.cpp`) cover both kwarg spellings and the per-face override.
- **Reference content**: `GameData/Materials/RustyMetal.ozmat` (multiply two world textures + height normal) with its baked PNGs, shipped via `materials.ozpak` (`build-data.ps1`). The reference world used to smoke-test the brush path was a throwaway and is not committed.

## Per-face surface properties (UT99 style)
- **Data model:** `Source/World/SurfaceFlags.{hpp,cpp}` — `oz::surface::{SurfaceProps, BrushSurface, SurfaceFace}`. **Raylib-free on purpose** (plain floats, no Color/Vector3) so `worldcheck`, `OzoneParser` and `tests/` link it. Same discipline as `ZoneTypes.hpp` / `GameType.hpp`.
- **A brush's surface is PER FACE**, not per brush: a brush-wide `def` plus up to six `face[]` overrides. Precedence is **face override → brush default → engine default** (the same "a value the author set always wins" rule the light defs use).
- **Faces are named in engine Y-up** (`px nx py ny pz nz`) and are **not** swapped for OZONE's Z-up — they are a renderer concept, not world coordinates.
- **`FaceFromNormal()` buckets by DOMINANT axis, deterministically** (ties resolve X→Y→Z). Both the editor's picker and the renderer's mesh split use it, so the face the user clicks is provably the face that gets edited. Do not depend on a primitive generator's vertex ordering.
- **Flags are `inline constexpr uint32_t` in `oz::surface`, re-exported unqualified via `using` at the bottom of the header — NOT macros.** They were `#define SURF_FAKEBACKDROP` / `SURF_COLLISION_PROXY` in `OzOzoneLoader.hpp`; a macro of the same name blocks any scoped declaration that mentions it, which is what stopped the flag set existing. `tests/Surface.test.cpp` asserts the two legacy bits never move.
- **Bit values are duplicated as `#define SF_*` in `GameData/Shaders/Surface.fs`.** Renumber a bit in the header and you MUST change the shader too, or the flag silently does nothing.
- **The legacy `OzonePrimitive::surfaceFlags` / `texScaleU/V` / `texOffsetU/V` / `texPath` fields are now DERIVED views** onto `BrushSurface::def` by `DeriveLegacySurfaceFields()`. `DrawWorldGeometry`, `DrawZoneGeometry`, `ApplyRenderableUV` and `ExportToOzone` still read them, and the shipped worlds rely on `flags=8` backdrops — do not write them from the tokenizer again, or a kwarg can be half-applied.
- **`surface.def.flags` OWNS the flags; `OzoneRenderable::surfaceFlags` is a derived mirror** of `oz::surface::kLegacyPipelineFlags`. Every writer must call `oz::surface::DeriveLegacyFlags()` afterwards. This is not bookkeeping — **`ExportToOzone` used to emit `flags=` only when `def.flags != surfaceFlags`, i.e. when the owner disagreed with its own mirror, which after a load is never.** So `flags=` was never written, and re-exporting a level silently deleted every painted backdrop and every AutoConvex collision proxy in it (TestMap lost all 230). `oz::surface::NeedsFlagsKwarg(defFlags)` is the honest predicate and is what the exporter now calls. `AddBrushRenderable` also used to assign `surfaceFlags` directly — the opposite direction from every other writer — so a freshly appended proxy exported a literal `flags=0`; it now sets `surface.def.flags` and derives. Pinned by `tests/Surface.test.cpp` (derivation + kwarg decision) and `tests/OzoneParser.test.cpp` (`flags=16` sets both fields, a plain brush sets neither).
- **`SurfaceMaterial` (`Source/Renderer/`) owns a SECOND shader program** (`GameData/Shaders/Surface.{vs,fs}`) rather than adding uniforms to `LitFog`. `Lighting.vs`/`LitFog.fs` drives every mesh, particle, pickup, projectile and the view-model; branching inside it would change the whole game's output. `Surface.vs` is a deliberate copy of `Lighting.vs` (same as `Wind.vs`).
- **Surface properties are UNIFORMS, i.e. per draw call**, so a decorated brush is drawn as up to six `DrawMesh` calls. `OzoneRenderable::faceMesh[6]` holds lazily built sub-meshes (`BuildFaceMeshes`); they own their own index buffers, so **`UnloadModel` does not free them** — `RemoveRenderable`, `Unload` and `UpdateBrushRenderable` must all `UnloadMesh` them.
- **A face sub-mesh must own EXACTLY one CPU array: `indices`.** `BuildFaceMeshes` borrows `model.meshes[0]`'s `vertices`/`texcoords`/`normals`/`colors` so `UploadMesh` can read them and upload its own VBOs, then **nulls all four before storing the Mesh**. `UnloadMesh` frees *every* CPU array a `Mesh` points at, not just `indices`, so a stored alias makes all four teardown paths (`RebuildSurfaceMeshes`, `RemoveRenderable`, `UpdateBrushRenderable`, `Unload`) free arrays `UnloadModel` frees again. The sentence above was true only of `indices` and read as if it were true of the whole array set, which is how this survived review: `UploadMesh` does NOT free its input in raylib 5.5, so nothing crashed at build time. **Symptom shape:** heap corruption detected (`STATUS_HEAP_CORRUPTION`) inside `ClearScene()` → `OzoneLoader::Unload()`, i.e. inside `EditorLog("Loading world: …")` and **before** the next `EditorLog("OZONE format: …")`. The level being opened is therefore never the level at fault — the *previously* loaded level poisons the heap, and 5 of the 6 shipped worlds carry `flags=8` backdrops that build face meshes on first draw. Opening `World.ozone` directly from `argv[1]` never reproduces it: nothing is rendered yet, so `BuildFaceMeshes` has not run. To reproduce, render ≥1 frame first, then File→Open.
- **A brush with no surface flags keeps the original single `DrawModel` path** (`NeedsPerFaceDraw()`), so the common case costs nothing. `DrawRenderable()` is the shared router; the fast path and the surface path must not drift.
- **Per-frame:** `SurfaceMaterial::UpdateFrame()` reuses `LitLightning_Update` rather than duplicating the 32-light loop — two copies would drift and a surface brush would disagree with the room around it. It is called from `Core.hpp UpdateLightSources` (after `LitLightning_UpdateFrame`) and from the editor's equivalent, because the program carries its OWN copy of `lights[]`/`viewPos`/`ambient`.
- **Glow** is two things: the emissive term is in `Surface.fs` (added *after* lighting, so a sign stays bright in an unlit room), and `OzoneLoader::DrawGlowGeometry` re-draws `SURF_GLOW` faces additively after the world pass for the halo. It is called from **two** sites — `Core.hpp` after `DrawWorldGeometry`, and `AngelEd/Source/Main.cpp` after `OzoneLoader::Draw` — because with only the client call site the halo was not authorable: the editor showed the emissive term but not the pass that the glow *colour* actually affects.
- **A face is drawn in EXACTLY ONE pass, enforced by `OzoneLoader::SurfacePass`.** `DrawSurface(r, pass)` takes `Full` / `GlowingOnly` / `BackdropOnly` and filters faces itself (`FaceBelongsToPass`). This used to be a convention spread over three functions, each filtering on `OzoneRenderable::surfaceFlags` — a mirror of `surface.def` **only** — and the two ways that went wrong are both real bugs: `DrawGlowGeometry` re-drew **all six faces** of any brush with one glowing face (so a wall with a single glowing sign picked up an additive ghost of its other five), and a **per-face** `SURF_FAKEBACKDROP` was invisible to the brush-wide filter, so it was drawn by the sky pass *and* the world pass. **Do not add a brush-wide flag filter to a pass entry point** — add the case to `FaceBelongsToPass`.
- **`SURF_ALPHABLEND` skips fog; `SURF_TRANSLUCENT` does not.** They used to be pixel-identical (`Surface.fs` OR'd them) while the header comment claimed otherwise, so the comment was false. AlphaBlend is for signage/decal-like surfaces that must stay legible at any distance; Translucent is a real physical sheet of glass and should recede in a foggy corridor.
- **`DrawZoneGeometry` no longer touches the shared `LitFog` uniforms.** It used to set `colDiffuse` to white and `ambient` to 5.5, then "restore" a hardcoded 1.0 — which meant every world surface drawn after the sky pass rendered at `ambient/10 == 0.1`, and the shader had no idea why its uniforms were wrong. It now sets one gain (`SurfaceMaterial::SetFullBright(0.55)`, reproducing the old `ambient/10`) and routes through `DrawSurface(BackdropOnly)`. `SetWorldAmbient()`/`GetWorldAmbient()` remain because `SurfaceMaterial::UpdateFrame` needs the world's ambient and raylib has no `GetShaderValue`.
  - **One deliberate visual change:** the old path also added `baseColor * colDiffuse * lightAccum` on top of the gain, so a backdrop in direct sunlight brightened with the sun. The full-bright branch has no light loop, so that term is gone — backdrops in sunlight are now uniformly 0.55×. That is the *point* of the flag (a painting whose panels brighten independently is not a painting), but it is a real change across the 69 shipped `flags=8` brushes and it was reviewed and accepted, not discovered later.
- **Four flags are INERT without a companion value**, because `Surface.fs` gates on the flag (so a zero speed is a hard no-op rather than a per-frame divide): `SURF_MASKED` needs `alphaCutoff > 0`, `SURF_GLOW` needs a non-zero `glowR/G/B`, `SURF_PAN_U`/`SURF_PAN_V` need a non-zero speed. `MaskedIsActive` / `GlowIsActive` / `PanIsActive` in `SurfaceFlags.hpp` are the single definition, `SurfaceHasInertFlags` reports one for a log line, and `SurfaceOps::ApplySurfaceEdits` calls `SeedInertSurfaceValues` so a freshly ticked checkbox never commits a combination that does nothing.
- **`SURF_FAKE_LIT` is ambient-only, and is NOT the same as `UNLIT`.** `Surface.fs` has two flat branches: `UNLIT|SURF_FAKEBACKDROP` → `baseColor * colDiffuse * uFullBright` (flat, scaled by the pass gain), and `FAKE_LIT` → `baseColor * (amb/10) * colDiffuse` (lit geometry, no light contribution). `FAKE_LIT` previously shared `UNLIT`'s branch, so it was a dead checkbox. **`FAKE_LIT` must never carry `uFullBright`:** the ambient term is a *floor* (0.1/10 == 0.01), not an exposure reference, so multiplying it by the 0.55 backdrop gain renders every shipped backdrop 100× too dark. That mistake shipped once and was caught only by rendering, not by reading.
- **`kBackdropGain` is a named constant in `SurfaceFlags.hpp`, not a local in `DrawZoneGeometry`.** It equals the old ambient/10 hack's gain (5.5/10), and `tests/Surface.test.cpp` asserts it. `SetFullBright` uploads **immediately**, never lazily: the caller sets it from inside the draw passes, which run *after* the frame's single `UpdateFrame`, so a deferred flush would never land. It shipped as a deferred flush once and `uFullBright` was permanently 1.0.
- **The Flags tab hides flags that have no consumer; it does not offer them dead.** `kSurfaceFlagRows` carries an `implemented` column. 13 flags parse, export and round-trip with **no consumer anywhere** (`SPECIAL_LIT`, `MIRROR`, `ENVIRONMENT`, `SMALL_WAVY`, `BRIGHT_CORNERS`, `DIRTY_SHADOWS`, `SHADOW_HI`, `SHADOW_LO`, `NO_SMOOTH`, `NO_BOUNDS_REJECT`, `ZONE_HACK`, `INVISIBLE_OCCLUDER`, `FORCE_VIEW_ZONE`) - of which only `DIRTY_SHADOWS` is planned to survive. `MIRROR` is shown-but-disabled and labelled `(planned)`, because it has a real design rather than being unfilled vocabulary. `SURF_COLLISION_PROXY` is absent entirely (AutoConvex-generated). **`tests/Surface.test.cpp` holds the register and fails if a flag is added to the dialog without a consumer, or if a new header flag is left unclassified.** Note `SURF_NO_SMOOTH` is the trap: the shader *reads* it and then executes `normal = normal;`.
- **A hidden flag survives an Apply.** `SpfReadControls` skips rows whose control is missing (`if (!c) continue;`), so a bit hand-set in a `.ozone` is not cleared by opening the dialog and pressing Apply.
- **Spot cones, effect tints and `intensity` are now real — do not reintroduce the old shapes.** `innerCone`/`outerCone` are **cosines** and are uploaded; they never were, so `smoothstep(0,0,x)` collapsed to 1 and every spot light was omnidirectional. `light.effect` is assigned in `BuildRLight`; it never was, so all four `applyLightEffect` tints were unreachable and torches were white. `intensity` is applied **once** — the old code pre-multiplied it into `light.color` *and* the shader multiplied again, so the contribution was `intensity²` (authored 0.5 rendered as 0.25). **Never pre-multiply `intensity` into the colour.**
- **`LitLightning_Animate` advances `phase` and NOTHING ELSE.** It used to overwrite `node.intensity` and `node.radius` with per-effect constants, so a torch authored `radius 12` became `45±10` every frame. Effect modulation now lives in the shader, where the colour tints already were. It is called **once per frame** from `LitLightning_UpdateFrame`, not inside `LitLightning_Update` — which runs once per shader *program* (LitFog and Surface.fs each call it), so animating there advanced phase twice and ran every flicker at double speed.
- **`phase` is a PLAIN ELAPSED-TIME CLOCK and `period` is scaled in the SHADER, exactly once.** `LitLightning_Animate` used to advance `phase += dt / period` while the shader then computed `w = phase / period`, so the divisor was applied **twice** — an authored `period 0.25` ran the torch flicker at 16× the intended rate. That was invisible only because the one shipped `.ozls` default is `period = 1`, where the two forms coincide. **Scale `period` in one place, not two.**
- **`Light::period` was declared in GLSL and never uploaded — every animated light effect was frozen.** Both shaders declared `float period;` in their `Light` struct and read it in `applyLightEffect()` with `period <= 0` meaning "no animation". The C `Light` struct had **no `period` member at all**, so there was no `periodLoc`, no `GetShaderLocation`, no `SetShaderValue`, and the uniform stayed at GLSL's default of 0 → `w` always 0 → every torch/fire/water/lamp rendered as a steady light with a correct colour tint and **zero flicker**. `Surface.fs` carried a comment asserting the upload happened; it did not. This is now the fourth member to have been "documented as uploaded and not" (after `innerCone`/`outerCone`/`phase`), which is why the invariant is now enforced rather than asserted — see below.
- **A GLSL uniform that no C++ code uploads is INVISIBLE to every existing parity test.** `test_surface`'s parity checks all compare *constants* between hand-maintained copies (`MAX_LIGHTS` ×3, `fogFactorAt` ×3, flag bits ×2). A missing uniform is a missing *member*, so every constant still matched and the scene still rendered. `test_light_uniform_upload_parity` now reads the GLSL `Light` struct and requires, per field: a C++ member, a `…Loc` slot, a `GetShaderLocation(shader, TextFormat("lights[%i].<field>"))` somewhere, and a `SetShaderValue` in `UpdateLightValues`. **When you add a field to either `Light` struct, this test tells you whether you actually wired it up.**
- **Flicker phase rides on the light (`lights[i].phase`), not on the slot index.** It used to be `float(i) * 2.399` — the uniform array index — so a light's flicker identity changed whenever the per-frame distance sort reordered the array. `period` is uploaded too, so the `.ozls` `period` stat finally reaches the shader. `isStatic` means "do not advance `phase`"; it does **not** bake anything (see `Wiki/Lighting-Plan.md` Phase B for when it will).
- **A directional light's source must not be the world origin.** Its direction is `normalize(position - target)` with the aim hardcoded to the origin, so `light directional 0 0 0` gives `normalize(vec3(0))` = NaN, which contributes nothing, still burns a budget slot, and counts as an active light (suppressing the camera fill light). `OzOzoneLoader` now warns and falls back to a straight-down sun. Four shipped suns had this bug.
- **`SURF_NO_BSP_CUTS` is real:** `RebuildCollisionVolumes` skips flagged brushes, so cosmetic geometry can opt out of collision. The skybox is a *special case handled earlier by a type check*, so the forced flag was never what kept it out — the docs claimed otherwise for as long as the flag had no consumer.
- **`SurfaceMaterial` carries its OWN `ambient` AND `fogStart/fogEnd/fogDensity/fogColor/fogIntensity`.** `CacheLocations()` used to cache no fog locations at all, so surface-flagged brushes always fogged at the GLSL defaults (10/100, density 1) regardless of the level's fog; and `UpdateFrame` hardcoded `amb = {0.1,0.1,0.1,1}` while its comment claimed the value lived on `OzoneLoader` — there was no accessor and it read nothing. `UpdateFrame(lights, camera, dt, ambient)` now takes ambient as a parameter and `SetFog()` mirrors the five fog uniforms (applied lazily, one upload per change). **`OzoneLoader` owns both** (`SetWorldAmbient`/`GetWorldAmbient`, `SetWorldFog`/`GetWorldFog`) because `Core.hpp` sets fog on `LitFog` from **three** sites (startup, zone entry, zone exit); `UpdateLightSources()` is the single mirror point instead of three that can drift. Both callers (`Source/Core.hpp`, `AngelEd/Source/Main.cpp`) read back from `OzoneLoader`.
- **Editor UX:** right-click a face → **Surface Properties (N Selected)** opens a `Flags` / `Alignment` / `Stats` dialog (`SurfacePropsProc`). **Shift**-right-click adds faces to the selection; `Apply` writes to all of them, `Reset Surface` drops their overrides. Picking is triangle-level (Möller–Trumbore in `Main.cpp`), not AABB-level, and the local→world transform must match `DrawSurface` or a rotated brush reports the wrong face.
- **`ApplyToSelection` is a no-op on an empty mask** — never let it mean "apply to all six faces". The editor reaches the same invariant through `ed::SurfaceEdit::isTargeted()`, which is `faceMask != 0` and nothing else.
- **Brush-wide scope is an EXPLICIT `bool brushWide` on `ed::SurfaceEdit`, never an overloaded `faceMask`.** It is what makes `flags=8` on a whole brush — the form all 69 shipped backdrops use — reachable from the editor; before it, *every* Apply wrote per-face overrides, so the brush-wide half of the OZONE surface vocabulary was hand-editing only. A brush-wide edit still requires a non-zero `faceMask` (the dialog was opened by right-clicking a face), so an empty mask stays a no-op regardless of scope. `SurfaceProps` for brush-wide comes from `surface.def`; `SetRenderableFace(idx, FACE_NONE, p)` is the write path and `ResetRenderableSurfaceDefault` the reset, because `BrushSurface::ResetToDefault` deliberately **keeps** `def`.
- **Every writer of `surface.def` MUST call `DeriveLegacyRenderable(r)`** (the `OzoneRenderable`-shaped wrapper over the raylib-free `DeriveLegacySurfaceMirror`). `SetRenderableFace` used to re-derive `surfaceFlags` *alone*, and that was **latent** only because nothing could write `surface.def` at all. `ExportToOzone` emits the brush-wide UV fields from the legacy mirrors and suppresses `surfTex=` whenever the mirror's `texPath` is non-empty — so a brush-wide texture or UV edit was silently discarded on save. The parser's twin for this is `OzoneParser.cpp`'s `DeriveLegacySurfaceFields(OzonePrimitive&)`; the four renderable-side writers are both load paths, `AddBrushRenderable`, `SetRenderableFace` and `ResetRenderableSurface*`.
- **A read-only properties-panel row MUST have no control ID.** `Apply`'s stat-edit scan reads each editable row by `controlId` via `readStatRowText()`, which returns `""` for a missing control - so an ID-less row would compare unequal to its authored value and be queued as an **erase**. This is why `FillDefBlock` filling `propDefEditable` for a *packaged* def also required gating the Apply scan on `propDefWritable`; otherwise the first Apply strips the def's own stats. The same trap applies to any new row type added to the panel.
- **Authoring:** brush-wide `flags=` / `surfTexSlot=` / `surfTex=` / `uvScale*` / `pan=` / `surfAlpha=` / `surfCutoff=` / `surfGlow=`; per-face `face<name>_<field>=`. Only overridden faces are exported, so a save is a small diff. `texSlot` is now BOTH a keyword (wins) and a legacy positional arg 8/9/7.
- **`skybox <tex> cx cy cz size`** is a render-only primitive: six inward-facing quads with direction-projected UVs, forced `UNLIT + TWO_SIDED + NO_FOG + NO_BSP_CUTS`, and **filtered out of the CSG collision pass** — feeding it to CSG would put an invisible wall around the player and let a `sub` erase the sky.
- `ApplyRenderableUV` recomputes from `OzoneRenderable::uvBase` (the pristine generated UVs). The old scheme divided by `texScaleU` to "undo" the last edit, but that field was seeded with the baked tiling for `BOX` only, so cyl/sph/pyr compounded on every edit and a box round-tripped to 256x.
- **A read-only properties-panel row MUST have no control ID.** `Apply`'s stat-edit scan reads each editable row by `controlId` via `readStatRowText()`, which returns `""` for a missing control - so an ID-less row would compare unequal to its authored value and be queued as an **erase**. This is why `FillDefBlock` filling `propDefEditable` for a *packaged* def also required gating the Apply scan on `propDefWritable`; otherwise the first Apply strips the def's own stats. The same trap applies to any new row type added to the panel.

## Title menu / pause menu

- **One active page, one shell.** `Source/Menu/TitleMenu.hpp` is a single-page
  menu (Home / Play / Multiplayer / Character / Settings), not the old floating
  pane desktop. Pages draw into `MenuMetrics::PageBody()` and return actions;
  `PlayHomeScreen` is the only place that calls `LoadWorld`, `LoadSave`,
  `LaunchHostedServer` or sets `g_quitRequested`. Do not reintroduce a pane
  z-order or process input for a page that is not active.
- **Every rectangle comes from `Source/Menu/MenuMetrics.hpp`.** It is raylib-free
  and covered by `tests/Menu.test.cpp`. The menu draws directly to the screen
  (not into `Target`) so a resize cannot leave it stretched. `UiScale` is the
  persisted user multiplier on the automatic DPI/resolution scale.
- **A menu entry is either functional or hidden.** No “coming soon” pages, no
  dead load buttons, no filter options for game modes that are not implemented.
  Continue is hidden unless a save resolves to a real world.
- **`PlayerProfile.modelPath` stores a character roster id**, not an asset path.
  The roster is `GameData/Pawn/Player/characters.cfg` (packed by `player.ozpak`),
  parsed by raylib-free `CharacterRoster`. Legacy paths map through
  `FindByMesh()`; unknown ids fall back to the `Player` def.
  `CharacterPreview` renders real portraits from `MeshCache`, not placeholder
  art. The server treats the id as untrusted and applies
  `net::SanitizeCharacterId` before the `PLAYER_PROFILE` broadcast.
- **`POS.sav` appended a world field (`x:y:z:level:world:`).** A missing field is
  legacy. `LoadSave` sets `g_savedWorldName`; campaign continue uses the mission
  world and only trusts the saved camera position when the world matches.
- **`AngelServ --world <name>`** pins the plain-co-op spawn world. It is ignored
  (with a warning) under `--campaign`, where the mission frontier owns join
  placement. Unknown world = startup error, never a silent fallback to world 0.
- **LAN discovery has an optional tail** (`;http=;map=;pw=`) appended to
  `OZRESPONSE`; old clients ignore it and old servers omit it. `PLAYER_PROFILE`
  is a new `MessageType` (32), so no `PROTOCOL_VERSION` bump.
- **Quit goes through `g_quitRequested`.** The pause menu, title Quit and native
  menu all set it; the single `CloseWindow()` at the end of `main()` remains the
  only close. Never call `CloseWindow()` from inside a frame or menu callback.
- **Pause settings keep the game paused.** `Escape` closes Settings first; the
  pause menu uses the same metrics/style and draws the frozen `Target` frame.
- **The pause TOGGLE owns Escape; the pause OVERLAY must not.** `Main.cpp`'s
  "Pause menu state" block flips `g_gamePaused` on the bindable `GameAction::Pause`
  and runs *before* the `if (g_gamePaused)` branch that calls `DrawPauseMenu`, so
  on the opening frame `IsKeyPressed(KEY_ESCAPE)` is still true. `DrawPauseMenu`
  returning `Resume` on that same press closed the menu on the frame it opened -
  toggle on, draw, toggle off, one frame - which read as "Escape does nothing in
  game". Do not reintroduce a key check in the overlay: the toggle is the single
  owner, and it is also the only form that honours a rebound Pause action.
- **`--menu-shot`** is the headless visual check (`Wiki/Menu-System.md`). Pure
  rules live in `tests/Menu.test.cpp`; LAN/profile wire rules in
  `tests/Network.test.cpp`.
- **Every pass through `Main.cpp`'s outer loop is a NEW session, and `ResetSessionState()` runs at its top.** `LoadWorld()` deliberately keeps the player's gear (a portal, a campaign transition and a server-driven mission move all reload the level around the same character), so the opposite case had no owner: a campaign's hotbar/backpack/level followed the player into a practice match and into multiplayer, and `SaveGame()` (called from `LoadWorld`) then wrote the stale loadout into `POS.sav`. The reset clears the LEM (hotbar/equipment/spell bar/instances + cached models), `gInventory`, the campaign mission + objectives, the view-model and portal latches. It runs **before** `PlayHomeScreen()` so a Continue can restore over it via `LoadSave()` — putting it after the menu (or inside `LoadWorld`) would either wipe the restored save or break in-session transitions. `Main.cpp` also clears `g_network_enabled`/`g_network_world_index`/`g_serverWorldNames` and disconnects there: a stale `g_network_enabled = true` made a subsequent practice match skip `UpdatePickups` entirely (it is gated on `!g_network_enabled`), so pickups looked broken after any multiplayer session. `SaveGame()` now skips `Campaign.sav` when no mission is active, because the empty serialisation used to TRUNCATE the campaign save on every practice/MP start.

## CI (.github/workflows/ci.yml)
- Runs on every push/PR; tags matching `b*` also create a GitHub Release. Release assets: `System-<tag>.zip` (full Windows bundle) plus per-binary downloads `AngelServ`/`AngelMaster`/`OzPack`/`Angels95` (`*-<tag>-{linux-x86_64,windows-x86_64.exe}`) and `AngelEd-<tag>-windows-x86_64.exe` (editor is Windows-only). `AngelServ`/`AngelMaster`/`OzPack` are self-contained; `Angels95`/`AngelEd` need the zip's DLLs+GameData.
- **The `deploy` job ships the two servers over SSH + systemd, on `b*` tags only.** It `needs: [linux]` (so `make test`, worldchecks and the GLIBC 2.39 gate passed on the exact tag), downloads those two artifacts, and runs in the `production` environment. Invariants, each of which is a way to destroy a live server:
  - `GameData/` is mirrored with `--delete` (a world removed upstream must leave the server's world list, or indices drift from clients), but `/Saves/` and `/Screenshots/` are excluded **on both the staging and remote rsync**. Without the excludes `--delete` erases player/world saves; without `--delete-excluded` rsync preserves excluded paths. `System/` deliberately has **no** `--delete`: it holds `OzServer.ini` (auth/admin tokens), logs and the cache.
  - A fresh install has no `GameData/Saves/` (it is gitignored and excluded from every deploy), and `GameState::save_world_state` `mkdir()`s `GameData/Saves/World<Name>` **non-recursively**, so `deploy-remote.sh` creates the parent before restarting. Otherwise the first autosave fails silently.
  - The units are checked in with the documented `/srv/angels95` path; `deploy-remote.sh` renders them to `DEPLOY_PATH` (default `/srv/angels95`, repo variable) before installing.
  - Both binaries are smoke-tested with `--version` on the runner (same `ubuntu:24.04` glibc base) and again on the host, then the script verifies `is-active` for every unit it installed (plus a 2 s stability re-check and `is-failed`, because `Restart=on-failure` makes a crash-looping unit briefly "active") and dumps `journalctl` on failure. **`DEPLOY_MASTER` defaults to `false`: only AngelServ ships.** The in-repo unit is opt-in and listens on **27910/27960** (`tools/angels95-master.service`), NOT the protocol defaults 27900/27950 - the hosted listing (`TribeWarez/angels95-master-server`) owns those, and b105 failed the deploy when the in-repo master tried to bind 27900. Advertise the in-repo one explicitly if used. A unit installed by an earlier deploy but no longer shipped is `disable --now`d automatically, so switching the flag off stops the stale master instead of leaving it in a restart loop.
  - Previous binaries are kept as `System/*.prev` for a one-step rollback. Redeploying a tag = re-run the tag's workflow; the job is idempotent.
  - Required secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`; optional `DEPLOY_KNOWN_HOSTS` (without it the job `ssh-keyscan`s, TOFU), variables `DEPLOY_PORT`/`DEPLOY_PATH`/`DEPLOY_MASTER`. The VPS needs `rsync`+`curl` and passwordless sudo for the remote script (which installs units and restarts services). Full runbook: `Wiki/Building.md` -> "Automatic server deployment".
- **Linux:** build raylib from source (cached) -> `make AngelServ` -> `make OTENGINE` -> `make ozpack` -> `make AngelMaster` -> smoke test with `timeout 3 ./AngelServ`.
- **Windows (MSYS2):** `pacman -S mingw-w64-x86_64-{gcc,make,raylib}` -> build all 5 targets -> assemble System/ -> run `build-data.ps1` -> upload artifact. Note: CI compiles AngelEd with inline raw `g++` commands, NOT the `AngelEd/Makefile` - the two can drift.
- **`make test` is the gate, and its EXIT CODE is authoritative.** It runs every suite in `TEST_SUITES`, each through `|| echo <name> >> build/failed_suites.txt`, prints the names of the failures and exits 1. Two traps this closes, both of which made CI lie:
  - The old recipe used `-./suite`, which tells make to ignore the status. That was deliberate ("one broken suite must not hide the rest") but meant a suite that **CRASHES** - segfault, uncaught exception, abort, which never reaches its summary line and prints no `FAIL` - passed make AND the `grep FAIL` step. Not hypothetical: a malformed-vec3 input exited `0xC0000409` with a green log. **Never reintroduce `-./suite`**, and never make the CI step depend on a log grep alone.
  - The suite list was written twice (prerequisites and one `-./suite` line each), so a new suite could be built and never run. `TEST_SUITES` is now the single list both read.
  `make test` also runs `tools/check_editor_objects.sh` and `worldcheck` over every shipped world, so neither can silently stop being exercised.
- **A malformed workflow file runs NO jobs at all, and nothing in the repo tells you.** `ci.yml` sat with five lines at column 0 inside the AngelEd `run: |` block for 50+ commits: the block scalar ends at the first un-indented line, the following `g++ ...` becomes invalid YAML, and GitHub reports "Invalid workflow file" while every job silently does nothing. Blank lines and comments inside `run: |` MUST be indented to the block's column. Validate before pushing: `python -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml', encoding='utf-8'))"`.
- **The Windows job RUNS the suites** (`make test`), not just builds. It previously only compiled, so a suite that breaks only under MinGW - a header glibc forgives, an MSYS2 path, a Windows API pulled into a shared TU - was invisible until a developer hit it. MSYS2's `sh` resolves `./test_parser` to `test_parser.exe`, so the same recipe works on both jobs.
- **`tools/check_editor_objects.sh` guards the two editor object lists.** CI hand-compiles AngelEd from an inline `g++` list rather than via `AngelEd/Makefile`, so an object can be added to one list and not the other - and an object that is COMPILED BUT NEVER LINKED produces no error at all, just missing code. The script compares the rule targets in `AngelEd/Makefile` against the `-o *.o` lines in `ci.yml` and against the link line, and is invoked by `make test` so it runs on both jobs and locally. Known exceptions: `AngelEd.res` (a windres resource, not a compiled object) and `OTCustom_stub.o` (CI links a stub where the Makefile links `-l:Custom.so`). If you add an editor object to both lists and the check complains, read the message - it names which side is missing.
